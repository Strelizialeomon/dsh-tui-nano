# ADR-20261022-input-history：输入历史按项目持久化，根输入跨会话、子代理仅会话内

- 状态：生效中
- 日期：2026-10-22
- 决策人：用户
- 适用范围：根输入框与子代理输入框的上键历史
- 取代：无
- 被取代：无
- 决策来源：`docs/specs/2026-10-22-nano-visual-followup/README.md` §3.4；用户 2026-10-22 选择「项目内跨会话」

## 决定

- 根输入历史写在 `<data_root>/history.jsonl`，创建时 0600，每行一个 JSON 对象：`display`、`timestamp`、`project`、`sessionId`。
- 只存已提交的输入文本；不存附件、图片、队列编辑或子代理输入。
- 上键只翻当前项目（canonical cwd）的记录：先当前会话，再同项目其它会话，最多 100 条。
- 子代理输入历史来自该子地址的本会话用户消息投影，不写文件、不跨会话。
- 草稿仍只存内存，关窗不跨进程恢复。

## 依据

- 对齐 Claude Code 的 `history.jsonl` 行为，满足用户「所有都可以回看」的要求。
- 不引入 paste store；长文本按原样存储。
- 不把历史写进官方会话记录，避免生成第二份会话历史。

## 否决了什么

- 仅当前会话的内存历史：重启即丢失，不满足跨会话回看。
- 跨项目全局历史：Claude Code 按 project root 隔离，本仓沿用。
- 把历史当作会话记录：历史只驱动输入回看，不驱动 transcript。

## 接受的代价

- 历史文件随输入量增长；读取从尾部扫描，最多凑 100 条。
- 附件与图片不能随历史恢复。
- 其他窗口写入的记录，需要重新读取文件才能看到（本版在进入浏览时读取）。

## 允许重开的条件

- 出现明确的跨项目回看需求。
- 历史文件增长影响启动或浏览性能。
- 需要附件/图片随历史恢复。
- 需要 Ctrl+R 历史搜索。
