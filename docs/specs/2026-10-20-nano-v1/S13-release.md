## 1. 边界

拥有 `tests/e2e/`、`docs/release/`、`packaging/`。提供安装包、版本矩阵、跨功能端到端验收、已知限制清单和发布结论。

不实现任何业务功能，不修改其他子件的协议或界面。发现子件缺失时记录为阻断项，不自行补写或用演示数据替代。

S13 额外拥有 `docs/release/design-contract.md`：统一键位、布局槽位、主题 token 和视觉基准的冻结契约。S13 只定义/冻结这份契约并做发布验收，不实现界面；各子件引用同一份契约，不能各自再定义一套键位或主题。

design-contract 的视觉基准固定为 `docs/design/2026-10-17-dsh-tui-ux-research/preview/index.html` 和同目录截图：dark/light 两套颜色 token、4ch 行号槽 + 2ch 标记槽、8 行差异预算、输入框上下各一条单单元格高的上下文线（左侧占比色段；正常 accent、约 80% warning、约 95% error、未知回退普通边框）、底部权限/瞬态/cwd、子代理状态灯（running 0.8s 闪烁、error 红、cancelled 黄、completed 绿，reduced motion 时静止）、装饰性 emoji 默认 0 个。间距以终端单元格为单位，不冻结浏览器 px、14px 字号或 22px 行高；字号由用户终端控制。

## 2. 支持矩阵

首版只宣称实际验证过的组合：

| 维度 | 首版承诺 | 不承诺 |
| --- | --- | --- |
| 平台 | macOS + Ghostty，全屏 | 其他终端、Windows、Linux、inline 模式 |
| 官方 Harness | `0.2.1-rc.2`（发布前必须实测的精确版本） | 其他版本、未知版本自动兼容 |
| 架构 | 待验证：arm64（本机） | 未构建的架构 |
| 语言/输入 | 待验证：英文、中文、系统输入法 | 未测输入法的组合行为 |
| 主题 | 待验证：Ghostty 深浅主题 + 60/100 列 | 任意主题或任意宽度 |

版本矩阵的唯一 owner 是 S13；S01 只提供宿主契约和实际版本行。矩阵必须记录构建号、官方提交、终端版本、macOS、CPU、Node 和验证日期。

未知官方版本必须显式拒绝执行；首版没有可证明的离线展示数据，因此不提供未知版本的离线只读模式。版本矩阵记录每个组合的构建号、官方提交、终端版本、macOS 版本、CPU 架构、Node 版本和验证日期。

## 3. 安装与启动

- 安装包包含 Rust 可执行文件、薄桥接插件和版本化的官方依赖声明；不打包用户凭据、会话数据或全局配置。
- 安装过程创建独立数据根（默认 `~/.dsh-tui-nano`），不覆盖 `DSH_HOME` 或其他 harness 配置。
- 首次启动顺序：profile 不存在时，先用 `dsh plugin --profile dsh-tui-nano add <bridge-package>` 初始化 base-backed profile；或 `dsh --profile dsh-tui-nano --from-default-profile <builtin>`，内置模板只能是 `web`/`headless`/`sdk`/`sdk-minimal`/`acp`。`--from-default-profile` 会替换已有 profile（删除依赖和 user patch），**只在 profile 不存在时用；升级/重装不得重跑**。profile 就绪后再装桥接插件、再启动宿主。配置、凭据和全局指令的实际来源必须显示；不复制凭据。
- 启动前核对 Node/dsh/桥接版本；缺失或版本不符时给出可操作错误，不静默降级。
- 卸载不删除用户会话和官方数据，除非用户显式选择；文档写明保留路径。

## 4. 跨功能验收

除各子件自己的验收外，发布前必须跑通以下真实组合：

1. **双窗口/会话认领**：同仓库不同 worktree、同 checkout 不同会话各开窗口；关闭 A 不终止 B；同一根会话第二个窗口在 S01 认领处被拒绝，调度未挂载。
2. **会话切换**：旧宿主退出、旧认领释放、新会话认领成功、新宿主拿写锁；草稿与阅读位置保留；失败显示无宿主，不保留假旧窗口。
3. **调度隔离**：`schedule` 只走 `nano-schedule-json`；两个根会话任务表互不可见；重启后同一根会话读到同一张表；周期补投只补最近一次；workspace/projection cache 按根会话隔离，会话列表来自共享 `sessions/`。
4. **跨会话内容隔离**：给每个根会话/子地址写入唯一标记，逐项检查 transcript、草稿、队列、附件（S06）、审批、问卷、终端、Monitor、调度在 UI、持久化和日志/诊断三个面都不出现另一地址的标记。例外只有官方 fork seed 和父对话 settlement notice；合法同文内容不算串会话，必须有标记才能判定。
5. **真实对话链路**：发送、流式、工具、差异、问卷、审批、压缩、子代理进入返回全部用真实后端，不用假数据。
6. **人工命令与终端**：`!` 用 trusted bypass（`danger-full-access`/`dsh-bash-local`）执行，输出作为合成 user 上下文注入且不立即唤醒模型；`!!` 只是原样交给 shell 的普通文本，`bash -c` 非交互、无 history expansion；PTY 输入/缩放/快照恢复；关闭清理与进程范围证据。
7. **Monitor**：真实任务输出触发真实 Agent 收件；预算耗尽可见；监听不消费模型游标。
8. **附件**：图片/通用文件发送、历史复用、失败整批回滚；会话事件不含路径/base64。
9. **技能与规矩**：真实技能调用、项目规矩来源、预算截断提示、工作目录变化重载。
10. **退出与崩溃**：正常退出、EOF、SIGTERM、Rust 崩溃、启动半途取消分别记录清理结果；不误杀独立 dsh。
11. **视觉符合性**：真实 Ghostty 中对照已冻结的 design-contract 和 `preview/index.html` 检查配色、层级、窄屏、CJK、选择复制、滚轮和退出；浏览器截图不能替代。

## 5. 证据标准

- 每项验收提供：命令/操作步骤、真实终端截图或录屏、关键日志、版本与日期。
- 截图/录屏必须在合成 home/workdir 下录制（如 `/tmp/nano-e2e-home`、`/tmp/nano-e2e-work`），或按固定规则遮罩；**用户真实路径**、用户名、主机名、密钥、PII、用户正文不得进入证据；合成路径本身允许出现。未脱敏原件只留在受控本机目录，不进 `docs/release/`。
- 证据绑定安装产物哈希 + 官方包完整版本/来源；commit 只作补充，因为官方包 `package.json` 只有版本号，commit 无法从安装产物自证。
- 自动化测试与人工记录分开；自动化全绿不等于视觉和交互符合。
- 无法复现或未测的部分明确写「未验证」，不写成「通过」。
- 已知缺陷必须列出影响范围、临时规避和是否阻断发布；阻断项未解决不发布。
- 证据存放在 `docs/release/<version>/`，随安装包版本一起冻结。

## 6. 完成标准

完成是有限承诺：

1. 本组规格约定的功能已实现。
2. 正常、异常、边界和回归测试通过。
3. 真实终端证据齐全，跨功能组合已验收。
4. 没有未处理的已知阻断缺陷。
5. 支持矩阵和已知限制与实际情况一致。

阻断缺陷定义（每条都要有可观察判据，不能只写「严重」）：

- **数据丢失/损坏**：权威会话、工具结果、调度任务、持久化事件丢失或损坏。可丢弃草稿/缓存不算，但必须在界面标为未保存/可丢弃。
- **凭据/用户内容泄漏**：密钥、凭据、PII、用户正文进入另一会话、日志、诊断、截图/录屏或发布包。检查面包含 UI、持久化、日志和证据。
- **跨会话串内容**：任一地址的 transcript、草稿、队列、附件、审批、问卷、终端、Monitor、调度出现在另一地址。例外只有官方 fork seed 和父对话 settlement notice。
- **无法启动/退出**：profile 初始化、宿主启动、会话创建/恢复、正常退出或清理失败到不可用。
- **权限/审批绕过**：UI、工具、终端、`!`、Monitor 或子代理在没有官方审批时扩大授权或改变策略。
- **会话无法恢复**：崩溃/重开后本可恢复的会话无法 resume/读取；上游明确限制不算，但必须在支持矩阵里写明。
- **交付物缺失/契约冲突**：某个子件的必需产物或契约不存在；键位、布局、主题 token 互相冲突且未按 design-contract 统一。

任一存在即阻断发布；把它披露成「已知问题」后再降级，不算解除阻断。

满足以上即宣布首版完成，不因为「再观察几天」无限延后，也不以「大部分可用」代替。未测平台和未实现功能如实列为限制，不宣称可用。

## 7. 失败与不变量

1. 发布结论只基于真实证据；不拿演示数据、浏览器样稿或检查点冒充终端验收。
2. 版本不符、能力缺失、损坏存储显式失败，不猜字段或创建替代成功结果。
3. 安装与卸载不覆盖用户配置和凭据；数据根边界与 S01 一致。
4. 自动化测试不能替代人工视觉/交互验收；人工记录也不能替代可重复的自动回归。
5. 阻断缺陷不因发布日期压力被降级为「已知问题」而不告知用户。
6. 发布审核档位由用户当场选择，S13 不自派审核、不自行宣布通过。
