# [2026-10-20-nano-v1/S09] 交互终端

- 组标识：`2026-10-20-nano-v1`；角色：子件 S09，单交付为真实 PTY、输入/缩放/屏幕恢复的交互终端。
- 状态：已实施（PR #25）；执行单 #12。
- 总纲：[共享约定与依据](README.md)。上游：S02（D02）、S01（D06/D07）。下游：S13（D09）。
- 合入前提：S01 的 PTY 双向流与背压契约可用，且 D07 的完整 snapshot/output/input 示例与断流证据齐全；S02 可运行（D02）。本份用真实 shell 进程完成输入、缩放、断线恢复和关闭验证。发布由 S13 承担。

## 1. 边界

拥有 `crates/nano-terminal/`、`bridge/terminal/`。提供 PTY 创建、附着、输入、缩放、屏幕快照恢复和关闭。

不实现命令日志伪终端，不实现 Agent 终端内核，不把终端输出写进会话 transcript，不替代操作系统权限。终端进程属于官方 user-terminal 服务；Rust 只负责显示和输入转发。

用户终端以系统用户权限运行，独立于 Agent 的沙箱模式和审批策略；操作系统与容器限制仍然生效，Nano 不提权。Agent 和 Monitor 不能借用户终端绕过审批。执行点：桥接只向 S09 的 UI 暴露 `terminal.create/attach/retain/close`，不把这些方法放进 Agent 工具表或 Monitor 投递路径；Agent 工具表没有用户终端入口，Monitor 只观察 S08 任务。

## 2. 创建与身份

- 新建终端在会话当前工作目录启动执行环境声明的默认 shell；provider 省略默认时按官方回退 `/bin/sh`。用户显式选择 shell 时使用发现的路径并再次验证；支持官方 `shellCandidates` 和记住上次 shell，缺失时回退当前默认。解析或传输失败时明确报错，不偷偷换一个 shell。
- 新终端使用官方新身份；终端 id 由 Nano 预生成并在 create 前持久化，create 对仍打开的同一 id 幂等。响应丢失/超时用同一 id 重试，不能用新 id 重试；已分配但未收到回执的 id 要先查询/关闭，避免孤儿占配额。关闭过的身份不能被延迟创建或重复创建复活，重开必须是新终端。
- 同一会话的终端数量、列数/行数、scrollback 和输入缓冲受官方限额约束；达到上限时拒绝并说明，不静默淘汰正在使用的终端。
- 宿主退出后终端进程结束；重新打开会话是新终端，不显示旧宿主终端列表，也不承诺恢复旧屏幕。
- 必须用官方 `retain()` 声明窗口持有，再 `attach()`；只 attach 不 retain 会在无人值守超时后被回收。窗口关闭时释放自己的 hold。
- 终端输出不进入 Agent 上下文；只有用户显式复制并粘贴到 S02 输入时，内容才可能进入模型。S08 的 `!` 是另一条一次性人工命令，不是终端屏幕的提交入口。

## 3. 附着、输入与缩放

1. 附着先收到 opening 快照（包含受限 scrollback 的最终屏幕，不是完整历史），随后按单调递增的 output sequence 接收增量；不从半屏开始猜。官方快照没有截断/缺失字段，无法判断是否被截断时不要伪造「缺口」标记，只标注「受 scrollback 限制」。
2. 每个附件有自己的命令序列号；输入与缩放都带序列号。控制权拒绝也回 ack，带 `refusal: read-only|not-running`；只有序列缺口、单条超过 `maxInputBytes`、越界 resize 才抛错并结束该附件。确认只表示提供方接受，不表示进程已执行。
3. 最新附件拥有输入和缩放控制权；旧附件失去控制后不能再写入。分离（detach）只释放控制，不杀进程。
4. 附着流提供官方 state 帧（`writable`/info）；控制权转移、rename、resize 和输出排空后会广播。进程退出时 Host 先禁用输入，最终 `info.state='exited'` 在 drained 之后才发布；客户端可能先收到 ack refusal，再收到最终 state。不能要求「进程退出时立刻有 writable=false 帧」；输入禁用和输出排空分别显示。
5. 未确认的输入不能在新附件中回放；重连建立新序列，避免重复按键。控制权转移或进程退出后的输入被拒绝，输出附件保持可用，输入禁用并说明。
6. 缩放携带真实行列数，受官方最大尺寸约束；客户端先 clamp/校验。Host 侧越界错误会结束该附件，进程和恢复屏幕保留；不把附件结束显示成普通拒绝。终端内容按 PTY 实际尺寸换行，Rust 不自行软换行后回写。
7. 客户端输入受未确认 UTF-8 字节预算约束；窗口满时本地等待，不无限排队。单帧放不下或缓冲耗尽时报 `inputFull` 并取消该附件，不回放已排队命令。
8. Rust 使用成熟的 VT 解析与终端渲染（如 tui-term/vt100 类库），不自写 ANSI 模拟器；解析器版本和兼容样本在实施时冻结。

## 4. 屏幕、滚动与复制

- 新附件通过官方快照恢复当前屏幕和受限 scrollback；快照之后的增量必须从对应 sequence 接上，缺口时重新附着，不拼接错位内容。
- 滚动区、光标、选择和应用模式由终端解析器状态决定；Rust 不把屏幕文本重新排版成聊天卡片。
- 选择复制使用当前屏幕的可见文本；宽字符、组合字符和换行按终端语义处理。复制不触发按键、不改变进程状态。
- 终端滚轮使用命令式滚动 + 微任务合并；按 Ghostty/xterm.js 分曲线，处理反向抖动和小数余量。终端以自身 scrollback 为主，不使用 transcript 的 sticky bottom；拖选/复制期间滚轮不破坏选择。
- 终端输出中的控制序列只影响终端渲染，不进入日志正文；诊断日志不记录完整屏幕或用户输入。
- 进程结束、输入禁用、输出排空和附件关闭是不同状态；显示时必须区分「进程已退出」与「输出已收完」。

## 5. 关闭、回收与多窗口

- 关闭状态用官方 client phase：`idle`/`loading`/`creating`/`connecting`/`connected`/`disconnected`/`closing`/`closed`/`failed`。close 失败标 `failed`，传输失败标 `disconnected`；没有 `cleanup-failed` 或 `unknown` 这两个官方状态。关闭等待官方清理和最终输出，失败保留资源可重试，不显示成已关闭。
- `closedIds` 是宿主生命周期内的内存集合；宿主退出后不保留，旧 id 可由新宿主重新创建。不承诺跨窗口崩溃墓碑，也不在启动时重试旧清理请求。
- 窗口持有终端时保留进程和有界屏幕；最后一个 hold 释放后，按官方无人值守超时回收。运行中、等待输入、已停止（SIGSTOP/SIGTSTP）或有后台工作的终端受保护；活动未知时清除空闲计时。必须用 `retain()` 增加 hold，不能只 attach。
- 每个窗口只操作自己宿主的终端；同一根会话不会有两个宿主（S01 认领），因此不存在跨窗口附着同一终端。其他窗口看不到该终端，也不共享屏幕内容。
- 断开连接后输出附件结束；宿主仍存活时进程和恢复屏幕可显式重连，宿主退出后进程结束，不承诺恢复。不自动重启进程，也不把断线当成进程退出。

## 6. 失败与不变量

1. PTY 进程、屏幕快照和输入确认的唯一来源是官方终端服务；Rust 不维护第二份终端状态作为真源。
2. 快照与增量必须按 sequence 连续；缺口只重附着，不拼接。
3. 未确认输入绝不回放；重连不重放按键。
4. 输入被拒绝不等于进程退出；输出附件保持，输入禁用并报原因。
5. 终端输出默认不进入会话和模型上下文。
6. 关闭失败不释放所有权；不显示成成功，也不让延迟创建复活旧身份。
7. 用户终端权限不因 Agent 的沙箱模式切换而改变。
8. 终端屏幕、输入和进程只属于当前根会话的宿主；切换会话后旧终端视图不显示新会话内容，也不把旧屏幕带入新会话。

## 8. 机制清单

| 机制 | 解决什么 / 没有会怎样 | 确认与代价 |
| --- | --- | --- |
| 快照 + 单调 sequence | 重连不丢屏、不拼接；没有则错位内容或半屏 | 官方契约；需处理 sequence 缺口重附着 |
| 附件级输入序列与 ack | 防止重连重复按键；没有则命令执行两次 | 官方契约；未确认输入不能回放 |
| Host 输入失败路径 | 序列缺口/超 maxInputBytes/越界 resize 结束附件；没有则 UI 误判普通拒绝 | 官方契约；进程和恢复屏幕保留 |
| 预生成 id + 幂等 create | 响应丢失不产生孤儿/重复 shell；没有则占满 maxTerminals | 官方 create 幂等；需持久化 id |
| state 帧 + `writable` | 控制权转移/rename/resize/排水后更新；没有则旧附件继续写入 | 官方契约；进程退出最终 state 在 drained 后 |
| 关闭身份不可复活 | 延迟 create 不能复活旧 id；没有则旧清理请求/新终端冲突 | 官方 host-lifetime closedIds；无跨窗口墓碑 |
| 进程退出/排水/附件关闭 | 三态分开；没有则把输入禁用当输出收完 | 官方语义；需分别显示 |
| 用户终端权限 + 执行点 | 只向 S09 UI 暴露 terminal 方法，不进 Agent 工具表/Monitor；没有则审批旁路 | 总纲 §5.4；需负向夹具 |
| `retain()` hold + 无人值守回收 | 打开中的终端不因超时被回收；没有则用户看着终端消失 | 官方契约；attach 不持有，必须 retain |
| 创建/shell 选择/配额 | 默认 shell、fallback、上限可预期；没有则起不来或静默淘汰 | 官方契约；需处理 shell 缺失 |
| 关闭/回收状态机 | 区分 closing/closed/failed/disconnected；没有则把未清理显示成已关闭 | 官方 phase；失败需重试 |
| 受限 scrollback + 有界屏幕 | 不把有界屏幕冒充完整历史；没有则用户以为看到了全部 | 官方限制；不伪造缺口 |
| 终端滚轮 + 选择优先 | 分设备曲线、拖选不误滚；没有则滚动手感不一致或选择被破坏 | 参照 Claude Code；需终端实测 |
| 输入字节预算 + `inputFull` | 防止慢消费者无限排队；没有则内存涨或按键丢失 | 官方限制；单帧过大需取消附件 |
| 每窗自持终端 | 不同根会话的终端互不可见；没有则串会话屏幕 | 用户硬要求；放弃跨窗共用同一终端 |
| 同一窗口多附件时最新附件独占输入 | 重连/多视图不抢输入；没有则两边同时打字 | 官方语义；旧附件只读 |
| 复用 VT 解析器 | 不手写 ANSI 模拟器；没有则显示错误且难维护 | 总纲证据 E18；依赖需冻结 |
| 终端输出不入转录 | 保持用户终端私有；没有则模型意外看到敏感输出 | 用户已确认默认不共享；显式提交才入模 |

## 9. 自定细节

- 终端视图的打开入口、标签和快捷键由 S09 定义；最终键位由 S13 的 design-contract 冻结，各子件引用同一份。
- scrollback 显示上限沿用官方配置；Rust 不额外保留第二份无限屏幕。
- 终端主题色按 S13 的 design-contract 主题 token 映射 ANSI 色；S09 不锁定具体色值。
- 首版只支持全屏模式；不做 inline 终端渲染。
- 复制行为优先使用终端自身选择，不新增「复制全部屏幕」按钮。
- 每个窗口只操作自己宿主的终端是作者设计；同一根会话的第二个宿主由 S01 认领拒绝，因此不存在跨窗口共用终端的入口。
- 不显示旧宿主终端列表、不在启动时重试旧清理请求，是作者选择：官方 client 在 localStorage 保存绑定和未完成 close 并启动重试；Nano 的宿主生命周期更短，不继承这套恢复。
- 回收测试使用缩短的 `unattendedTimeoutMs` 和受支持 shell（`bash -i`/`zsh -i`）；未知 shell 的 idle 是 unknown，不自动回收。
