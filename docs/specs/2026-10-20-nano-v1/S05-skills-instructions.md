# [2026-10-20-nano-v1/S05] 技能与规矩

- 组标识：`2026-10-20-nano-v1`；角色：子件 S05，单交付为技能发现/调用与项目规矩来源展示。
- 状态：已批准实施；执行单 #8。
- 总纲：[共享约定与依据](README.md)。上游：S02 输入；官方技能与指令服务。下游：无。
- 合入前提：S02 命令入口可用；本份用真实技能目录和真实项目规矩文件验证发现、调用与刷新。发布由 S13 承担。

## 1. 边界

拥有 `crates/nano-skills/`、`bridge/skills/`。提供用户可调用技能列表、`/name` 入口、技能说明预览，以及项目/全局规矩的加载来源与刷新事实。

不实现自建指令解析器，不解析 `@path` 导入，不自动写跨会话记忆，不替代官方技能后端加载技能正文。技能的发现、合并、优先级和正文读取都由官方 `skills` 注册表与文件 provider 决定；S05 只呈现和发起调用。

## 2. 技能发现

技能目录来自官方后端对当前会话的发现结果，不靠 Rust 自行扫描目录重建。

- 只列出官方标记为 `userInvocable` 的技能；`modelInvocable: false` 的技能仍可由用户调用，并带「仅用户可调用」标记。
- 每个条目至少显示名称与描述；来源路径只在官方提供时显示，不猜路径。
- 名称冲突、provider 不可用、发现失败时，保留最后一次可用目录并标注「可能不完整」，不把失败当成「没有技能」。
- 目录按会话缓存；官方文件 provider 自带 watcher，变化时调 `invalidate()`，注册表再发 `skills/change`。S05 只订阅这个信号并重新拉目录，不自建第二套 watcher；`watch:false` 时没有官方失效信号，不能假装实时。
- 只有 `ctx.skills.snapshot().complete=false` 才显示「可能不完整」；官方 `skills/list` RPC 没有 completeness 字段，若要显示必须由 `bridge/skills/` 供数并经 S01 契约暴露，否则不显示。名称冲突是官方确定性 first-wins，不是「不完整」。
- 预设切换、插件管理操作、连接重置后也重新获取。缓存不能凭空显示已删除技能，也不能因为一次发现失败清空全部技能。
- 技能正文只在调用时读取；浏览列表和预览说明不加载正文，也不激活冷会话。

## 3. 调用

1. 用户在输入框输入 `/name` 或从建议中选择；发送的文本保持字面量，不替换成别的内容。
2. 名称同时匹配宿主命令时，命令优先，客户端在成为 prompt 之前就完成裁决；不能把技能误发成命令或反之。
3. 官方在下一步确定性地注入技能正文；Rust 不二次拼接、不改写、不摘要正文。调用结果作为普通对话内容进入 S03 的 transcript。
4. 技能调用是一次真实的上下文注入，会计入模型成本；界面不能宣称「没有额外消耗」。
5. 调用失败、技能被删除、正文读取失败时，官方宿主对未知/已删除/被关闭用户调用的名字**按普通 prose 通过，不报错**；S05 不能伪造一个官方不产生的错误。用户要确认是否注入，只能看模型侧是否出现 `skill-invocation` 正文；界面可以标注「未注入」，但不能断言「技能已删除」。
6. 用户显式 `/name` 没有 tool call、没有参数，只是带 `skill-invocation` source 的用户消息加注入正文；技能卡片渲染归 S03，S05 只提供发现/预览/调用入口，不拥有 transcript 卡片。模型侧 `skill` tool 的调用行由 S03 按工具行渲染。

## 4. 预览

已知技能可以在发送前查看说明文件：

- 预览读取官方 catalog 给出的指令文件路径，只读打开，保持 token 可编辑。
- 没有文件路径的技能仍可调用，但不提供预览入口，不伪造内容。
- 预览是当前窗口的查看行为，不写入会话、不改变模型上下文。
- 路径不可读、文件被删除或超出读取上限时显示错误，不显示空内容冒充成功。

## 5. 项目规矩与全局指令

项目规矩由官方 `agent-instructions` 在会话内加载，S05 只展示来源和生效事实。

- 来源顺序为：用户全局链（`$DSH_HOME/AGENTS.md`、`<agentsHome>/AGENTS.md`），再到项目根至会话工作目录的目录链；每个目录先 base（`AGENTS.md`/`CLAUDE.md`）再 local overlay（`AGENTS.local.md`/`CLAUDE.local.md`）。根目录的 local overlay 早于更深目录的 base，不是整条链的尾巴。展示按官方实际加载顺序，不自己重排。
- 重复内容按官方规则合并；同一候选组里 `CLAUDE.md` 与 `AGENTS.md` 内容相同只渲染一次。界面说明「已合并」，不重复列成两份。
- 规矩在首次请求形成基线，之后依赖成功的文件读写或会话恢复来发现变化；不承诺监听外部编辑器。界面显示「最近一次加载」的来源与时间事实，不能宣称实时同步。
- 超出字节预算时，官方会省略较宽的整个文件并提示被省略/截断的路径；S05 必须显示这条预算提示，不能静默截断。
- 工作目录变化会在下一次请求前重载适用链；切换后显示新的来源集合。
- 加载失败（权限、I/O、根标记探测失败）显示官方错误，不换成祖先目录或空规矩冒充成功。
- 不解析 `@path` 导入；不自行展开 include；不把项目规矩复制成 Nano 私有配置。
- 首版没有自动跨会话记忆：不写记忆文件，不把对话内容持久化成「规矩」。用户显式编辑官方指令文件属于普通文件操作，由 S08/编辑器处理。

## 6. 失败与不变量

1. 技能目录、技能正文和项目规矩的唯一事实源是官方服务；Rust 不保存可写副本。
2. 目录不完整时保留上次结果并明确标注；不能因一次发现失败清空全部技能。
3. `/name` 的字面量、命令优先级和官方注入语义不能被 UI 改写。
4. 项目规矩的加载顺序、去重和预算截断以官方为准；界面只展示，不重算。
5. 预览与调用分离：预览不注入上下文，调用不依赖预览是否打开。
6. 被删除或改名的技能不复活旧正文；历史调用保留已记录正文，当前目录按最新发现显示。
7. 自动记忆写入不在首版范围；任何「记住这个」的需求只能作为后续独立规格。

## 8. 机制清单

| 机制 | 解决什么 / 没有会怎样 | 确认与代价 |
| --- | --- | --- |
| 官方技能目录 + 字面量调用 | 保证同一 `/name` 在各入口一致；没有则菜单与手输解析不同 | 官方契约；调用会确定性注入正文并计费 |
| 官方 provider watcher + `skills/change` | 磁盘新增/改名/删除/正文编辑能刷新目录；没有则技能列表过期 | 官方因果链；S05 不自建第二套 watcher |
| 只读预览 | 发送前看说明文件，不加载正文/不激活冷会话；没有则只能盲选 | 官方 `path`；无路径不预览 |
| 目录不完整保留上次结果 | 单次发现失败不清空技能；没有则用户误以为技能全没了 | 官方观察语义；只有 `snapshot().complete=false` 才标不完整 |
| 规矩来源与预算展示 | 用户能核对项目规矩从哪来、是否被截断；没有则暗中丢规则 | 官方加载语义；不是实时监听 |
| 不做自动记忆 | 避免把对话内容误写成长期规则；没有则隐私和一致性风险 | 总纲已定；后续独立需求 |

## 9. 自定细节

- 技能建议列表的排序沿用官方目录顺序与名称前缀优先，不另造评分。
- 预览在右侧栏或独立只读面板打开，具体位置由 S13 的 design-contract 冻结。
- 「最近一次加载」只显示会话内可观察的加载事实，不推断文件系统修改时间。
- S05 不提供技能安装、卸载或市场入口；首版只用已安装技能。
- 文件监听和防抖由官方 provider 负责（默认 200ms/100ms，microtask 合并）；S05 不自建 1s/500ms/300ms 那一套。只有 `watch:false` 时才明确标注「不会自动刷新」。
- 预览的读取大小上限是 S05 自定细节；官方只保证提供 `path`，不定义预览上限。实现须设一个明确上限并显示截断。
