# [2026-10-20-nano-v1/S07] 会话与上下文

- 组标识：`2026-10-20-nano-v1`；角色：子件 S07，单交付为会话选择/重启、命名、上下文查看与压缩。
- 状态：草案，未批准实施；Issue：待规格合入后创建。
- 总纲：[共享约定与依据](README.md)。上游：S02 契约、S01 生命周期（D02/D06）。下游：S13（D09）；D10 是 S13→全部子件的发布条件。
- 合入前提：S01 的会话认领/受控重启可用，S02 可运行（D02）；本份用真实会话恢复、命名和压缩验证。发布由 S13 承担。

## 1. 边界

拥有 `crates/nano-sessions/`、`bridge/sessions/`。提供会话列表与选择、主会话受控重启、会话命名、上下文占用展示和手动压缩入口。

不实现调度规则（S11）、不直接读写官方日志、不复制官方标题算法、不实现第二套上下文测量。会话存储、标题、投影、用量和压缩都由官方服务拥有。

## 2. 会话身份与选择

- 会话身份是官方不透明 `sessionId`；不用工作目录名、窗口标题或文件路径推断身份。
- 新建走官方 `session.create`；恢复走 `ctx.sessionController.resolveAgent(sessionId)`，存在性检查用 `inspect()`。官方 Remote 没有 `session/resume` 端点，不能去找一个不存在的 resume。
- 命名 `sessionId` 仅在官方条件满足时复用（空白、同目录、未归档、无其他 writer）。已开始、目录不符、被占用时官方会保持原会话并 mint 一个新 ID；S07 **不接受静默新建**，create 返回不同 ID 即硬失败，不能把新 ID 当成用户要的会话。
- 恢复被现有写句柄占用时返回 `session/writer-held`：提示已有窗口占用，不删除锁、不强接管、不降级成新会话。`session/conflict`/`session/agent-busy` 是 create 侧的目录/Workspace/子代理归属错误；resume 侧除 writer-held 外可能折叠成 `gateway/internal`，要分别显示并说明来源。
- 列表来自官方会话查询/投影，只显示官方字段（标题、最近活动、agentAvailable、running、blank、cwd、formatStatus）；不推断「可恢复」，不自行用首条消息伪造持久标题。标题缺失时显示官方回退值或「未命名」。
- 选择会话不激活它的子代理，也不在列表阶段打开冷会话正文。

## 3. 主会话切换与重启

一个窗口只驱动一个主会话树。切换主会话必须走 S01 的受控重启：

1. 通过 S02（草稿/光标）和 S03（阅读位置）的接口请求保存；S07 不自己持有或复制草稿/锚点状态。窗口进入明确的「切换中」状态，不显示成已切换。
2. 停止当前主会话的新动作，取消活动回合，停止该会话的调度和 Monitor 投递，按 S01 退出顺序清理本窗口拥有的资源。
3. 旧宿主完全退出后，释放它的会话挂载认领；宿主未退出时不得提前释放。不能在线替换认领或 storage 路由，也不能让旧主会话在后台继续运行。
4. 新宿主启动后，先认领新根会话，再创建或恢复会话；认领失败就停掉新宿主，显示「被 pid X 占用」，保留草稿和阅读位置，不新建替代会话。
5. 认领成功后再处理官方写锁：已物化的会话确认官方写锁；新建 blank 会话在首次 materializing write 前没有官方锁，此时认领就是前置互斥。失败则停掉新宿主、释放认领，显示「当前没有可用宿主」和重试/返回入口，不保留一个看似活着的旧窗口。
6. 重启失败、半启动、旧宿主未清理干净时，不自动重试或偷偷开新会话；按 S01 的 `failed`/`cleanup-failed` 报告。

恢复与新建必须分开：

- **恢复**：目标会话必须已存在；走 `resolveAgent`，不调用 create。`session/not-found`、损坏或不可迁移的会话显示明确错误，绝不创建一个同 ID 的空会话冒充恢复。除 writer-held 外的 resume 失败可能只有 `gateway/internal`，需要 `sessionQuery` 的错误码补充说明。
- **新建**：`rootSessionId` 由 Nano 预生成并传给官方 create；create 返回不同 ID 即硬失败。
- 命名 `sessionId` 的复用条件以官方为准：空白、同目录、未归档、无其他 writer。已开始、目录不符、被占用时按官方结果处理，不能靠 create 的静默新建兜底。

同仓库不同会话可以各开一个窗口；同一根会话不能被两个窗口同时驱动。S07 不实现项目级单实例锁。

## 4. 命名

- 标题来源以官方为准：首条合格用户消息的回退标题、异步生成标题或用户显式重命名，新者胜。
- 用户重命名走官方 `rename()`；成功后标题持久化并出现在列表，不进入模型上下文。
- `rename` 会先 `resolveAgent(sessionId)` 再 `titles.rename(liveSession)`，冷会话会被 resume、拿写锁并产生新的 live Agent。因此只允许给当前活动会话改名；列表里的冷会话必须先打开，不能偷偷起第二个主会话。
- 重命名失败保持旧标题并报错；不能先本地改名再等官方。
- 删除、清空标题不是首版能力；不提供官方没有的重置入口。
- 自动标题失败只告警并保留旧标题；不阻塞主回复，不生成替代标题写入本地。

## 5. 上下文与压缩

- 上下文占用是参考值，不是计费记录：占用 = 下一次请求的 `contextPressure.projectedTokens` ÷ 同一投影的 `contextWindow`。`contextWindow` 是最近一次 `request/context` 记录的容量，不是按当前模型目录现查；两者缺一就显示「未知」。
- `contextPressure.pressureTokens` 是最近一次 provider 报的 prompt 大小，surface 一变就可能过期；它不能单独当「当前占用」。`tokenUsage` 是整个持久日志的计费用量，不是上下文大小；`contextBreakdown` 是启发式构成，不是计费或精确值。三者必须分开展示，不能统称「精确用量」。
- 切换模型后，旧的 `contextWindow` 可能和新 pressure 短暂错配；界面标出「最近一次记录」和时刻，不假装实时。
- 启发式按固定字符比例估算，CJK 和 JSON schema 会明显低估；界面必须标注近似，不显示成唯一真值。
- 手动压缩只通过官方 `/compact`，且只在会话空闲、没有正在进行的压缩时可用。`/compact` 需要 `ctx.commands` 命令适配器，入口由 S04 的命令路径提供；没有适配器时只保留自动压缩，不伪造手动入口。有活动回合或压缩进行中时显示官方不可用原因。
- `/compact` 不接受参数；用户传参时显示官方用法错误，不自行解释参数。
- 压缩成功后被替换的是官方选定的较老区段，最近历史不动；界面显示被压缩条数和估算节省 token，不显示成「删除了消息」。
- 压缩期间提交的 prompt 进入队列，压缩结束后按序开始；不丢失、不重排。
- 压缩可以取消：取消只停止等待，后端仍会完成清理并落 `Compaction cancelled.`；此时历史可能已经改变，必须从官方记录重读，不能保留旧 transcript 或把取消显示成「什么都没发生」。
- 断开连接或超时后结果未知：先查官方当前会话状态和压缩记录，不自动重试、不重复 `/compact`。
- 压缩改变历史后的会话状态以官方记录为准；失败时按官方稳定消息报告（历史变化、无有用摘要、未干净结束、保存失败等），不自行重试。
- 自动压缩的触发条件由官方决定；S07 只展示状态，不实现自己的阈值或压缩算法。

## 6. 失败与不变量

1. 会话、标题、用量和压缩事实的唯一来源是官方服务；Rust 不保存可写副本。
2. 切换失败不丢草稿、不误杀其他窗口、不留下半启动宿主；失败后显示可恢复的「无宿主」状态，不保留一个看似活着的旧窗口。
3. 恢复失败不创建替代会话；create 返回不同 ID 即硬失败。writer-held 只来自 resume，create 的静默新建不能当兜底。
4. 切换或恢复失败后，当前窗口不得继续显示上一个会话的 transcript、草稿、队列、审批、问卷、终端、Monitor 或调度内容；只显示按地址属于当前会话的数据。
5. 上下文数字必须标注来源和近似性；`projectedTokens`/`contextWindow` 缺失时显示未知，不补零、不拿累计用量冒充。
6. 压缩是官方动作，不是本地截断；取消或断流后历史可能已变，必须从官方记录重读，不自动重试。
7. 关闭窗口不承诺跨进程恢复草稿；会话历史仍可从官方恢复。
8. 会话选择和主会话切换不改变其他窗口的会话所有权；同一根会话的第二个窗口在 S01 认领处被拒绝。
9. S07 不持有草稿、光标或阅读锚点；只通过 S02/S03 的接口请求保存/恢复，避免第二份状态互相覆盖。
10. 重命名只对当前活动会话开放；冷会话改名会 resume/拿写锁，不能偷偷起第二个主会话。

## 7. 验收

- [ ] 用真实会话列表恢复一个已有会话，历史与官方一致；标题、最近活动正确。
- [ ] 恢复走 `resolveAgent`/`inspect`，不调用不存在的 `session/resume`；`session/not-found`、损坏、不可迁移时明确报错，不创建同 ID 空会话；writer-held 之外可能只有 `gateway/internal`，要说明来源。
- [ ] 新建时 Nano 预生成 ID，官方 create 返回同一 ID；返回不同 ID 时硬失败，不把新会话当成功。
- [ ] 双窗口同根会话在 S01 认领处被拒绝，第二个窗口不创建新宿主、不挂 schedule；不删锁、不接管、不降级。
- [ ] 切换主会话时旧宿主完全退出、旧认领释放、新会话认领成功；已物化会话拿官方写锁，blank 会话以认领为前置互斥；任一步失败显示「无宿主」和重试，不保留假旧窗口。
- [ ] 切换或恢复失败后，transcript、草稿、队列、审批、问卷、终端、Monitor、调度列表都不出现上一个会话的内容。
- [ ] 重命名成功持久化并在重开窗口后可见；冷会话改名被拒绝并提示先打开，不能起第二个主会话。
- [ ] 未命名、空会话、冷会话、恢复会话的标题与列表状态符合官方投影；列表不推断「可恢复」。
- [ ] `/compact` 在空闲时可用，运行中/压缩中显示官方不可用原因；成功显示条数与估算节省，队列不丢不重排。
- [ ] 压缩取消后显示 `Compaction cancelled.` 并从官方记录重读历史；断流结果未知时不自动重试、不保留旧 transcript。
- [ ] 压缩的每一种预期失败显示官方稳定消息，不自动重试、不显示成成功。
- [ ] 上下文占用用同一 `contextPressure` 投影的 `projectedTokens / contextWindow`；缺一显示未知；标出「最近一次记录」和时刻；`tokenUsage`、`contextBreakdown`、`pressureTokens` 不与占用混为一谈。
- [ ] 本份的真实会话/压缩证据与失败夹具随交付提供；未测的自动压缩边界明确标注。

## 8. 机制清单

| 机制 | 解决什么 / 没有会怎样 | 确认与代价 |
| --- | --- | --- |
| 认领 + 受控重启切换主会话 | 保证旧会话不偷偷运行、schedule 表不串；没有则双写或双 timer | 总纲已定；切换有一次完整启停成本 |
| 恢复/新建分离 | 防止恢复失败时静默创建空会话；没有则用户以为历史回来了 | 官方契约；create 返回不同 ID 必须硬失败 |
| 会话认领 + 官方写锁 | 防止路径猜身份和多窗口争写；没有则可能打开错会话 | 官方契约 + S01 账本；blank 会话认领为前置互斥 |
| 冷列表只读/不激活 | 列表阶段不打开正文、不激活子代理；没有则列表变慢或串会话 | 官方契约；只显示官方字段 |
| 官方标题 + 活动会话改名 | 标题持久且不进入模型；冷改名会 resume，必须拒绝 | 官方语义；重命名需往返 |
| 官方 `/compact` + 取消/未知态 | 复用官方压缩和测量；没有则本地截断破坏历史或丢状态 | 官方约束；压缩只能在空闲时运行 |
| 占用只读 `projectedTokens / contextWindow` | 不拿累计用量或启发式冒充当前占用；没有则显示错数字 | 官方投影；缺一显示未知 |

## 9. 自定细节

- 会话列表的排序沿用官方「最新优先」；S07 不另造分组或收藏。
- 切换主会话的入口和确认文案由 S07 定；最终键位由 S13 的 design-contract 冻结，不交给 S02。
- 上下文占用的视觉位置按 S13 的 design-contract 布局；S07 只提供数值、来源和近似标记。
- 首版不提供归档、删除或跨机器恢复会话的界面。
- 手动压缩失败后不自动重试；由用户再次触发。
- 切换失败后的「无宿主」状态、重试和返回入口由 S07 定义；它不是一个新的主会话，也不恢复旧会话。
- 恢复与新建的判定顺序（先 `inspect`/`resolveAgent`，再决定是否 create）由 S07 定义；不能把 create 当成通用的「打开会话」。
- 标题缺失时的「未命名」占位是 S07 自定细节；不写回官方标题，也不把它当持久名称。
- 冷会话改名一律拒绝并提示先打开；这是作者设计，避免列表操作偷偷 resume 并拿写锁。
