- 组标识：`2026-10-20-nano-v1`；角色：子件 S03，单交付为可读的 transcript、代码差异、问卷与审批界面。
- 状态：草案，未批准实施；Issue：待规格合入后创建。
- 总纲：[共享约定与依据](README.md)。上游：S02；运行输出观察依赖 S08（D11）。下游：S12（D04）、S08/S10（D08 审批/权限发布闸）。
- 合入前提：S02 消息与焦点接口可用；本份用真实工具结果、真实审批请求和真实问卷完成展示与回答验证。发布由 S13 承担。

## 1. 边界

拥有 `crates/nano-transcript/`、`crates/nano-decisions/`、`bridge/decisions/`。提供阅读层级、过程降噪、原位展开、代码差异、问卷与审批的展示和回答入口。

不拥有模型选择、推理强度、命令和权限写路径（S04），不拥有附件（S06），不拥有子代理导航（S12），不解析官方会话存储文件。审批是否发生、允许什么、拒绝什么由官方权限服务决定；S03 只呈现请求并把用户答案交回。

### 1.1 给 S12 的展示接口

S03 导出两种 transcript 视图给 S12：只读视图用于 one-shot 历史和外部叶子（若有记录），可交互视图用于 continuable 子对话；两者复用同一渲染器，不复制第二套。接口至少带地址、消息/工具/差异节点、决策卡入口和阅读锚点；S12 只导航和挂载，不直接读 child Session 原始日志，也不另建输出文件。

S03 不生成第二份 transcript。所有正文、工具调用、工具结果、失败和答案都来自 S02 建立的官方事件身份；展示层可以降噪和折叠，不能改写原文、增删事实或猜测未记录的字段。

## 2. 阅读层级

默认视图按「回答 → 待办 → 过程」组织：

| 内容 | 默认展示 | 展开方式 |
| --- | --- | --- |
| 助手正文 | 正常亮度，完整保留；结论和小标题按 Markdown 结构强调 | 原文直接阅读、选择、复制 |
| 思考 | 单行状态与用时，正文收起 | 点击该行展开；再次点击收起 |
| 命令 | 首个可视行 + 隐藏行数 + 状态 | 点击命令/输出区域原位展开 |
| 运行输出 | 最新 2 个可视行，原位更新 | 同块展开查看更多 |
| 完成输出 | 有依据的简短结果或退出状态 | 同块展开完整可用结果 |
| 失败 | 独立错误摘要与退出状态，不折叠隐藏 | 详情可滚动核对 |
| 代码差异 | 文件、`+N -M` 统计、4ch 行号槽（有坐标才写数字）、整块差异 | 整块内容点击展开；无额外按钮 |
| 问卷/审批 | 独立焦点卡，占用输入位 | 不并入普通消息折叠 |

规则：

1. 思考、命令、运行输出和代码差异都是「可视行预算」，按终端实际换行后的行数计算，不按源文本行数。CJK、制表符、超长单行和窄屏都计入。
2. 同一条消息内的多个过程块共享预算，但每个块独立开关；展开状态不因工具完成、新消息到达或另一条消息展开而自动收起。
3. 代码与 Bash 的展开入口是整个内容区域的原位点击，不是标题旁的小按钮，也不引入过渡动画。拖选、复制和链接操作优先，不能因鼠标拖选误折叠。
4. 普通助手正文不跟随工具块折叠。界面只呈现传入的 Markdown 结构，不自动猜测哪一句是最终回答，也不额外调用模型生成摘要。
5. 流式输出完成、窗口宽度变化、用户滚动时必须保护当前阅读锚点；新增内容不得把用户正在读的位置顶走。是否「跟随最新」由用户位置决定，不靠固定滚动。
6. 折叠只改变显示，不改变会话记录、模型上下文和工具实际输出；展开后复制到的仍是真实内容。
7. 运行输出只在官方事件或 S08 的任务观察提供时原位更新；已结束的工具卡不附加后续 job 输出。没有来源时不显示「运行中」的假预览。
8. 合成 bash 记录（`<bash-input>`/`<bash-stdout>`/`<bash-stderr>`，来源 `bash-mode`）按来源显示并保留原文；不渲染成普通用户提问，也不能作为审批依据。

### 2.1 滚动实现（参考 Claude Code）

- **命令式滚动**：滚轮/键盘直接改视口偏移并标脏，多次事件用微任务合并成一次渲染；不要每个滚轮事件触发一次完整重排。
- **sticky bottom**：默认吸底；用户上滚立即脱离，回到底部再吸底。吸底状态是显式信号，不用「scrollTop + viewport == scrollHeight」事后推断。
- **跳转到消息**：`scrollToElement` 把元素引用交给渲染阶段，在同一布局 pass 里读位置；不要先算一个数字再等 throttle 渲染。
- **虚拟化**：只挂载视口 + overscan；未测量项按低估值，覆盖计算按悲观值；挂载总数、单次新增数、滚动位置量化都要有上限。初始预算参照 Claude Code：overscan 80 行、未测估高 3 行、悲观 1 行、挂载上限 300、单次新增 25、量化 40 行；实施时在 Ghostty 复测后冻结。
- **滚轮**：原生终端、Ghostty 预乘、xterm.js 的事件率不同，必须按设备/终端分曲线；处理反向抖动和 fractional 余量，不能全局一个倍率。初始常量参照 Claude Code，必须在本项目目标终端复测。
- **滚动优先**：滚动期间抑制 IDE/LSP/GC 等后台轮询的下一 tick，避免和滚动抢事件循环。
- 这些是显示层机制，不改变 transcript、模型上下文或工具实际输出。

## 3. 工具记录与代码差异

工具调用与结果的配对、生命周期和递归子调用以官方事件为准。S03 不自行拼装 call/result，不把准备中的参数当成已执行。

- 每个工具行保留业务身份和状态；失败、被中断、被拒绝、结果未知必须显式，不能显示成成功。
- 有退出码时显示真实退出码或信号；缺失退出码时明确标记「未知」，不能补零或猜成功。
- 参数与结果按原始字段展示；路径、文件名只在官方记录存在时显示。工具结果的 `FileDiff`/`FsDiffMeta` 没有增删统计字段、没有逐行坐标；`workspace-changes` 的 turn 级 diff 有 `added`/`deleted`/`oldStart`/`newStart`，但那是整轮摘要，不能贴到单个工具卡。工具卡统计由 `oldText`/`newText` 本地计算，UI 只显示 `+N -M`，不显示来源标签；来源说明放详情/诊断。`write` overwrite 的 `oldText` 是 null，删除数不可知：只显示已知新增，或不显示删除数，不伪造 `-0`。保留 design-contract 的 4ch 行号槽和 2ch 标记槽：只有官方/工具结果提供真实 patch 坐标时才逐行填数字，没有就留空；不复制 demo 的合成行号。`FileLocation.line` 是 read/insert 的焦点行，不是 diff 坐标。
- 代码差异使用统一的增删底色和行内变化强调；块头放文件名与 `+N -M`，不显示来源标签；待应用与已应用状态分开。
- 长差异默认最多 8 个可视代码行，多个修改段共享预算，优先保留第一处完整变更；超长单行的续行也计入。隐藏范围必须明确提示。
- 整块点击展开后仍是同一份差异，不提供「复制修改后代码」或「展开原始差异」按钮；系统文本选择与复制保留。
- 不支持或格式异常的工具结果回退为原始文本，不丢弃、不伪造结构化字段。
- 图片、搜索结果、Web 结果等专用展示只在官方结果提供对应字段时启用；否则用通用文本回退。

## 4. 问卷

问卷卡占用输入位，是场景上的独立焦点，不改变底层会话归属。视觉和行为沿用已确认的 Pi 风格：

1. 单列编号；标题与说明分行；焦点指针与已选项分开，焦点不等于答案。
2. 单选：焦点始终在选项或 Other 上；Enter 选中焦点项并提交，数字键直选。多选：空格切换勾选；Enter 不暗加焦点项，单题内提交所选，多题 batch 里翻到下一题。多题最后整体提交走「提交页」：最后一题 Enter 先翻到提交页，再在提交页 Enter 或确认按钮提交；不是最后一题直接提交整批。焦点指针必须可见。这是 design-contract/样稿的交互基线；官方 Web 的「Enter 提交整批不选中」不照搬。
3. Other 行内输入；多选草稿在打开或编辑 Other 时保留已选标签，提交项可以同时带 `selected` 和 `custom`；单选的自定义答案保持互斥。
4. 多题可分页回看；Enter 在 batch 里翻到下一题，不直接提交整批；最后一题 Enter 翻到提交页，再在提交页 Enter/确认按钮整体提交。缺项返回第一个未完成题，不静默跳过。
5. Skip 保留其他草稿，并为该题提交既有的空结果；Skip 不是取消整张卡。
6. 关闭卡片不等于作答：有关联工具调用的请求，关闭只离开输入位，工具行可以重新打开；没有关联调用的请求，关闭即取消整个等待并明确告知。
7. 结果契约是每题 `{ id, selected, custom? }`，不是只有 `selected/custom`。官方没有独立 Notes/Chat 通道时不画空入口，不发明无法回传的结果字段。
8. 限时问卷按官方剩余时间倒数；焦点、编辑或显式「多给点时间」可以暂停或转为不限时。到期后等待以 `ASK_TIMED_OUT` 结束、Agent 可以继续，但问题仍可回答；此时 open 已转 continued，答案改走 `userQuestions/answer`，提交在途时要重新武装。倒计时和草稿只属于本窗口。
9. 已结束的问卷以只读卡回看：选项和输入禁用，Skip 与提交消失，跳过的题明确标记；关闭只移除展示，工具行可从同一记录重建。
10. 一次只有一个问卷请求拥有卡片；后来的 pending 请求等前一个解决后再显示，不能抢占或把答案落到错误请求。
11. 问卷卡按地址归属；切换会话或子对话后旧卡不显示，未决请求不跨地址作答。

问卷答案提交后是「已提交」，不是「已执行」。live 答案直接回给等待中的官方请求，不走 inbox；提交是 sent-not-confirmed，卡片保持草稿直到投影关闭。另一窗口先结算时，gateway 会静默丢弃迟到结果；只有 continued 路径已有 pending steer 时才报 `REPLY_QUEUED`，不能把「静默丢弃」写成「已处理错误」。

## 5. 审批

审批只在官方权限服务发出真实请求时出现，不为每条 Bash 添加强制确认。

- 卡片先说明工具名和官方 `reason`/`displayReason`，再显示能关联到的待执行命令。官方请求不携带工具参数；只有 `callId` 存在且能关联到带 `command` 字段的工具调用时才显示完整命令，否则只显示工具名和原因，不猜命令、不放空命令区。
- 命令区域可滚动核对，不受聊天卡片的紧凑预算限制。
- 只提供官方允许的结果，通常是一次性允许与拒绝。官方没有「始终允许」「记住规则」「Other」「先讨论」时，界面不画这些选项，也不能把关闭弹窗当成允许。
- 默认拒绝/取消/不可用，绝不默认允许。官方 `ApprovalOutcome` 只有 `allowed-once`/`rejected`/`cancelled`/`unavailable`，没有 `timeout`；本地超时只能映射到 `cancelled` 或 `unavailable`。默认焦点放在拒绝，Enter 不直接提交允许；允许需要显式选择。
- 键盘与指针共享同一个待处理请求锁：已撤回或被替换的请求不能再接受答案，前一次失败不能解锁后一次请求。
- 拒绝和允许都写入官方审计事件；界面不改写审计原因，不把模型生成的文案当成本地化展示文案。
- 审批请求不属于模型上下文；S03 不能把审批卡内容作为额外系统提示注入。
- 审批是 turn 内的实时请求，`approval/asked|decided` 是 log-only，没有投影。同一宿主 generation 内，pending scoped waterfall 会跨连接重连 replay：收到同一 request 就恢复卡片。进程重启或回合结束不会补 `approval/decided`，只可能留下 `TOOL_OUTCOME_UNKNOWN` 和 `turn/end: interrupted`；此时显示「结果未知/已中断」，不重建可操作卡。
- 同一根会话只有一个宿主（S01 认领），不存在另一个窗口处理同一审批；切换会话后旧审批卡不显示。

计划审阅（官方 `plan-review` 意图）使用紧凑卡：显示计划标题和两行摘要，提供查看完整计划和「批准 / 请求修改」。批准返回官方批准标签；请求修改取消本次等待并把反馈交回输入位，不提交批准。没有官方意图时不自行生成计划卡。

## 6. 焦点、失败与恢复

- 问卷和审批是焦点栈顶的显式交互；它们占用输入位时，普通输入不抢按键。IME 组合态、输入控件和文本编辑优先于快捷键。
- 限时问卷由官方 `userQuestions` 投影重建；默认 blocking 问卷**不进投影**，重连靠 pending request 再投递，已结束只读卡靠 transcript 记录重建。timed 模式由 S01 的 profile 配置 `tool-ask-user` 的 `mode: timed`（active preset 的 config，不是顶层 `--patch`）；S03 只消费，未配置时按 blocking 路径处理。
- 本窗口未提交的问卷草稿可以恢复，但只有 tool-call-keyed 请求能跨重载恢复；unkeyed legacy 请求不能。不能由草稿证明请求仍然有效。
- 迟到的问卷回答按官方记录只显示一次；折叠进历史后可通过工具行或轮次展开回看，不重新打开可提交状态。
- 展示失败（缺字段、未知工具、损坏记录）显示可读回退和明确错误，不阻塞会话其余部分，不创建替代成功结果。
- 问卷和审批的答案、卡片和草稿按地址归属；切换会话/子对话后不显示上一个地址的卡片或答案。
- 退出或切换场景不自动回答未决请求；未决请求保持未决。连接重连后仍可处理；进程重启按结果未知/中断处理，不伪造可操作卡。
- 审批和问卷的答案不能被折叠动作藏掉；过程降噪不适用于这两个焦点卡。

## 8. 机制清单

| 机制 | 解决什么 / 没有会怎样 | 确认与代价 |
| --- | --- | --- |
| 可视行预算 + 原位展开 | 长过程不刷屏，又能按需核对；没有则正文被日志淹没或只能砍内容 | 用户已确认；展开多一次点击 |
| 命令式滚动 + 微任务合并 | 滚轮不触发整树重排；没有则滚动掉帧 | 参照 Claude Code；需终端实测 |
| sticky bottom + scrollToElement | 吸底/跳转不依赖过期位置；没有则跳转错位或回底失灵 | 参照 Claude Code；需显式状态 |
| 虚拟化 + overscan 预算 | 长会话不撑爆内存；没有则 1000 条消息数百 MB | 参照 Claude Code；初始值实测后冻结 |
| 稳定阅读锚点 | 流式/宽度变化不顶走阅读位置；没有则用户一直被动 | 用户已确认；需地址挂接 |
| 分设备滚轮 + 滚动抑制后台轮询 | 滚动手感一致、不掉帧；没有则速度异常/卡顿 | 参照 Claude Code；需终端实测 |
| 整块点击开关 | 不新增小按钮，拖选复制不误触；没有则点击标题的窄入口难用 | 用户已确认；需处理选择手势 |
| 统一差异块 | 文件名、`+N -M`、4ch/2ch 槽位、有坐标才填行号、增删色；没有则代码变更不可辨 | 用户已确认；统计本地计算，来源放详情 |
| write overwrite 无 before-image | 删除数不可知，不伪造 -0；没有则统计撒谎 | 作者设计；只显示已知新增或标 coarse |
| 单列问卷与焦点/选择分离 | 避免焦点冒充答案和多题误提交；没有则多选/Other 结果错 | 用户已确认；多题多一次整体确认 |
| 每题 `{ id, selected, custom? }` | 官方答案批次要求逐题 id；没有则整批被拒 | 官方契约；不能只传 selected/custom |
| 限时 continued / `ASK_TIMED_OUT` | 到期后仍可回答，答案改走 userQuestions/answer；没有则提交走死通道 | 官方 timed schema；需 profile 开 mode: timed |
| 问题提交状态机 | sent-not-confirmed、静默丢弃、`REPLY_QUEUED` 分别处理；没有则误报已提交 | 官方 live/continued 路径；需区分 |
| 待处理请求锁 + 宿主代际 replay | 撤回/替换后不能再答；重连 replay 同一 request；没有则重复答案或丢卡 | 官方 scoped waterfall；跨连接、非跨进程 |
| 只呈现官方审批选项 | 不擅自扩大授权；没有则界面看起来能「始终允许」而实际无此语义 | 官方能力；只能一次性允许/拒绝 |
| 审批默认焦点拒绝 | 防止 Enter 误放行；没有则用户没读完就批准 | 作者建议；与 Web 的 Enter=approve 不同 |
| 问卷只读回看 / 审批只显示 outcome | 限时问卷有投影、blocking 靠 transcript，审批是 log-only；没有则伪造审批卡 | 官方能力；三类来源不能共用一种回看 |
| 跨地址卡片隔离 | 旧问卷/审批不带到新会话；没有则串会话答案 | 用户硬要求；需在验收覆盖 |
| D04 只读/可交互展示接口 | S12 复用同一渲染器；没有则第二套 transcript | D04 契约；S03 独占渲染 |

## 9. 自定细节

- 代码差异默认 8 个可视行、命令 1 行、运行输出 2 行、思考 1 行，均为本项目建议值，不是官方统一规则。
- 忙碌指示只保留一处；完成、失败和终止状态保持静态，不持续动画。
- 展开/收起复用整块点击与现有详情入口，不新增专用快捷键；具体键位由 S13 的 design-contract 冻结，S03 只引用。
- 已结束问卷的回看入口放在工具行；没有工具行的请求只保留历史记录，不另外造入口。
- 主题色值按 S13 的 design-contract 主题 token；S03 不锁定生产色值。
- 审批卡默认焦点在拒绝、Enter 不直接允许，是作者设计；官方 Web 的 Enter=approve 不照搬到 TUI。
- 审批请求没有 `callId` 或关联不到工具参数时，不显示命令区域；这是作者设计，避免猜命令。
- 本地审批超时只能映射到 `cancelled`/`unavailable`；官方没有 `timeout` outcome。这是作者设计。
- 限时问卷需要 S01 的 profile 显式配置 `tool-ask-user` 的 `mode: timed`；未配置时按 blocking 处理，不伪造 timed 投影。
- 官方 diff 没有每工具增删统计和逐行坐标；S03 的统计是本地从 `oldText`/`newText` 计算，但 UI 保持 design-contract 的 `+N -M`，不加「本地统计」字样；行号槽保留，有真实坐标才填数字。
- `write` overwrite 的 `oldText` 是 null：删除数不可知，不显示删除数或标 coarse，不伪造 `-0`。这是作者设计，必须进验收。
- 视觉以 S13 的 design-contract 为准；design-contract 的基准是 `docs/design/2026-10-17-dsh-tui-ux-research/preview/index.html` 和同目录截图（4ch 行号槽、2ch 标记槽、8 行差异预算、颜色/间距）。S03 不另定颜色/间距/行高，也不把 demo 的浏览器 px 直接冻结成终端值。
