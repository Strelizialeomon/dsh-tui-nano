# [2026-10-20-nano-v1/S04] 模型与权限

- 组标识：`2026-10-20-nano-v1`；角色：子件 S04，单交付为命令入口、模型与推理强度切换、权限预设与审批策略读写。
- 状态：已批准实施；执行单 #7。
- 总纲：[共享约定与依据](README.md)。上游：S02 命令入口，S01 官方服务。下游：D08 的消费者。
- 合入前提：S01 官方服务可用、S02 输入路由可用；本份用真实模型目录和真实权限服务验证读写。发布由 S13 承担。

## 1. 边界

拥有 `crates/nano-controls/`、`bridge/controls/`。提供命令面板、模型目录与选择、推理强度选择、权限预设切换，以及这些选择的展示事实。

不实现审批卡的展示和回答（S03）、不实现执行策略内核、不修改官方权限判定、不自行解析 provider 凭据。选择是否可用、请求是否被允许由官方服务回答；S04 只发起官方写入并把结果如实显示。

## 2. 命令入口

S02 提供统一的输入路由；S04 提供命令业务和命令面板。

- 命令列表来自官方命令服务；名称相同的技能与命令冲突时，命令优先（官方 skill UI 契约）。
- 面板显示命令名、说明和当前可用状态；不可用命令明确原因，不隐藏成「不存在」。
- 执行命令走官方命令路径，不在 Rust 侧重新解释命令参数或伪造结果。
- 命令执行结果进入 transcript 的方式由 S03 呈现；S04 不另建第二份输出区。
- 命令失败、被拒绝、结果未知分别显示，不把「命令已发出」显示成「命令已完成」。

S04 不新增官方没有的命令语义；本项目自有入口（例如底部状态跳转）只能是纯视图动作，不伪装成命令。

## 3. 模型与推理强度

模型选择以官方提供的当前会话模型目录为准，身份是精确的 `provider + model` 对，不是模型显示名。

- 目录按 provider 分组；当前选择不在目录中（模型被移除、凭据退出、目录刷新）时显示占位和原因，不用别的模型顶替。
- 切换只影响下一次请求的组装；正在运行的步骤保留它开始时已经组装的模型和强度。
- 推理强度只列出该模型 adapter 声明的档位；没有 reasoning 元数据时不画强度行，不提供任意数值输入。
- 默认值来自模型自身的强度元数据；会话可以显式选择，未选择时显示「默认」而不是伪造一个具体档位。
- 选择成功以官方返回为准。拒绝时保持原选择并显示错误；不乐观更新成新模型。
- 模型切换会在下一次请求前由官方写入变更提示；纯强度变化不产生额外提示。S04 不自行生成模型提示文本。
- 官方 `selectModel` 成功回执只确认会话内选择，不等待「新会话默认值」保存；默认值保存失败只告警。界面不能把「已切换」说成「默认值已保存」。
- 已寻址的子代理会话不暴露独立的模型选择入口；子代理的模型由官方会话策略决定。

## 4. 权限与审批策略

权限选择使用官方权限预设，不把沙箱模式和审批策略拆成两个可任意组合的开关。

- 预设列表来自官方进程目录；当前会话的选择来自官方投影。未匹配任何预设的组合显示为 `custom`，用户可以离开但不能把它选成命名预设。
- 用户切换走官方 `/permission <preset>` 命令路径（`setPolicy`，会向模型注入「changed by the user」）；不直接调用 `permissionPresets.set()`，避免无模型通知、半切换和 no-op 行为不一致。
- 官方预设写入不是事务：先写 preset 身份，再分别写 sandbox/approval。任一步失败或断流，必须先重读官方投影，显示实际值（可能是 `custom` 或半切换），不能宣称「保持原状态」。
- 官方没有的预设、`auto` 集成未启用时的 Auto 行、以及任何「始终允许」语义，都不能由 S04 伪造。
- 审批策略只有官方提供的 `ask` / `never` 语义；切到 `never` 会由官方通知模型，界面必须显示完整后果，不能只说「更少打扰」。
- 权限变更扩大授权时必须有明确的用户动作；外部事件、Monitor 或子代理不能替用户点这个变更。
- 写入失败、被官方拒绝、结果未知时先重读官方当前值；结果未知不能显示成「没变」或「已变」。

## 5. 展示事实与底部状态

- 底部默认只保留权限/安全状态、运行或错误瞬态和工作目录；模型、推理强度、上下文数字、缓存、成本和 Token 不常驻。
- 精确的模型、强度和权限值从 `/model` 和 bare `/permission` 查看（官方没有 `/status`）；上下文占用按 S13 的 design-contract 显示，S04 不另造第二条状态栏。
- 当前值必须能追溯来源：来自官方目录/投影的显示为事实；目录尚未加载、刷新失败或不可用时保留最后值并标「可能过期」，Host/连接 reset 才清空。
- 同一根会话只有一个 writer（S01 认领）；第二个窗口的模型/权限写入会被拒绝，不存在「两个窗口同时改、以最新事件合并」。写入失败按 writer-held 处理，不接管。

## 6. 失败与不变量

1. 模型目录为空、凭据缺失、模型不可路由时，允许保留旧选择并显示原因；不自动换模型、不改写已保存的选择。
2. 模型选择、权限切换和策略写入都是「可失败的动作」，不是本地开关；没有官方确认不显示成功。
3. 命令、模型和权限的业务事实只有一个来源：官方服务。Rust 不缓存成可写的第二份配置。
4. 切换模型或权限不取消正在运行的回合，也不清空队列；只有官方终止或用户显式停止才改变活动回合。
5. 关闭窗口或切换会话不自动重置权限；恢复会话时读取官方当前值。
6. 审批策略与审批卡的回答是两件事：S04 可以改策略，但不能替 S03 的未决请求作答。

## 7. 验收

- [ ] 用真实模型目录展示 provider 分组、当前模型和强度；目录为空、模型被移除、凭据退出时显示原因且不替换模型。
- [ ] 切换模型后下一次请求使用新路由，运行中的步骤保持原路由；拒绝时保持旧值。
- [ ] 只有模型声明的强度可被选择；无 reasoning 元数据时不显示强度行，不能输入任意值。
- [ ] 真实权限预设切换走 `/permission <preset>`（`setPolicy`），模型侧收到 changed-by-user；不直接调用 `set()`；no-op 行为与官方一致。
- [ ] 写入失败、被拒绝、结果未知时先重读官方投影并显示实际值（含 `custom`/半切换）；结果未知不显示成「没变」。
- [ ] 同一根会话第二个窗口的模型/权限写入被拒绝，按 writer-held 处理，不接管。
- [ ] 官方没有 `/status`：模型/强度/权限从 `/model` 和 bare `/permission` 查看；目录刷新失败保留最后值并标可能过期，Host reset 才清空。
- [ ] 模型切换成功只确认会话选择；默认值保存失败只告警，不显示成「默认值已保存」。
- [ ] 底部只显示约定的常驻字段；精确值从面板或状态命令可得。
- [ ] 命令名冲突时命令优先；不可用命令显示原因；命令失败不显示成完成。
- [ ] 本份的目录/权限夹具和真实服务证据随交付提供；未测的第三方 provider 明确标注。

## 8. 机制清单

| 机制 | 解决什么 / 没有会怎样 | 确认与代价 |
| --- | --- | --- |
| 精确 `provider + model` 身份 | 显示名会重名或变化；没有则切错模型或回显错值 | 官方目录契约；需要处理目录移除 |
| 只列模型声明的强度 | 避免任意数值造成不可控请求；没有则强度选择不可验证 | 官方元数据；部分模型没有强度行 |
| 权限预设整体切换 | 沙箱与审批必须成组变化；没有则用户组合出官方未验证的状态 | 官方预设；`custom` 只能离开 |
| 单一官方事实源 | 防止本地缓存覆盖官方策略；没有则多窗口和恢复时状态漂移 | 总纲已定；刷新失败显示未知 |

## 9. 自定细节

- 命令面板的列宽、搜索和快捷键由 S04 定，最终键位由 S13 的 design-contract 冻结。
- 底部字段的视觉位置由 S13 的 design-contract 统一；S04 只提供字段事实，不新增常驻项。
- 模型目录加载失败时保留最后一次显示的值并标注「可能过期」，不自动清空。
- 本项目不提供 `custom` 预设的命名保存；用户只能切回官方预设或保留官方当前组合。
