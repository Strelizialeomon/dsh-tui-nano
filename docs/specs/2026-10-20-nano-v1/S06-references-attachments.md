# [2026-10-20-nano-v1/S06] 引用与图片

- 组标识：`2026-10-20-nano-v1`；角色：子件 S06，单交付为文件引用补全、图片与通用附件发送。
- 状态：已批准实施；执行单 #9。
- 总纲：[共享约定与依据](README.md)。上游：S02 有序输入，S01 附件接口。下游：无。
- 合入前提：S02 输入模型可用；本份用真实附件服务和真实图片链路验证上传、发送、历史复用与失败。发布由 S13 承担。

## 1. 边界

拥有 `crates/nano-attachments/`、`bridge/attachments/`。提供 `@file` 补全、路径引用、图片与通用文件的选择/上传/移除，以及提交时的有序附件清单。

不读取文件内容来生成引用，不解释技能，不拥有会话真源，不实现图片压缩算法或存储后端。附件的规范化、限额、持久化和请求版本由官方 attachment 服务决定。

## 2. 文件引用

- `@path` 只在输入开头或空白之后触发补全；邮箱等词内 `@` 不触发。
- 路径含空格时使用 `@"path with spaces"`；目录候选保留结尾引号以便继续下钻，选中目录后闭合引号。
- 相对路径从当前会话工作目录解析；绝对路径保持宿主路径。格式化器拒绝控制字符和无法安全表示的引号。
- 候选来自官方针对当前 Agent 工作目录的发现结果；补全只给路径，不读内容、不预加载文件。
- 选中候选只是把引用文本插入 prompt；模型仍需调用文件工具才能读取内容。界面不能暗示「已附上文件」。
- 补全请求可取消；慢响应不能覆盖更新的输入或插入到已移动的光标位置。

## 3. 图片

- 支持 PNG、JPEG、WebP、GIF，具体大小、像素、尺寸限额由部署配置决定，不在界面写死来源上限。
- 每张图片在消息被接受前完成检查、规范化和持久化；任何一张被拒绝，整条消息失败，不发布部分附件。
- 发送的图片在 prompt 里是 base64 `data`（官方 `PromptContentPart.image`），持久引用只在官方准入后生成；会话事件和日志不含 base64 或本地路径。不能把「官方持久引用」当成 wire 格式。
- 图片在后续回合和重启恢复后仍可复用；读取历史时校验字节与记录一致，缺失/损坏/被替换必须报错，不能静默显示错误图片。
- 图片只作为有序内容列表的一项，不改变文本顺序；多张图片保持用户选择顺序。
- 当前模型不支持图片输入时，整条消息被官方拒绝（`MODEL_DOES_NOT_SUPPORT_IMAGES`/`session/attachment-invalid`）；界面在发送前显示原因，不把失败说成网络错误。
- 界面预览必须与实际发送对象对应；预览失败时不得发送一个未确认的附件。

## 4. 通用文件

- 非图片文件按原字节保存，不设文件类型白名单和大小上限（以部署实际能力为准）。
- 模型收到的是一行确定性句柄：文件名、字节数、摘要前缀，以及在执行文件系统能映射时提供的只读保存路径；不是文件字节。映射不到时句柄明确说「当前执行环境无法访问可读路径」，不假装有路径。
- 附件列表显示文件名、大小和状态；摘要或真实路径由官方记录提供，Rust 不自行计算后冒充官方摘要。
- 音频、视频没有专门处理，按通用文件处理并如实说明；不宣称能被模型直接「听/看」。
- 子代理只接受图片，且需要模型支持；通用文件上传在子代理一律被官方拒绝，不提供入口。
- 已保存附件不会被自动删除；引用感知的清理不在首版。

## 5. 上传、回执与提交顺序

图片和通用文件走两条不同链路：

- **图片**：选择后在本地编码/预览，提交时作为 base64 `data` 进入 prompt；官方在准入时检查、规范化、持久化。没有预上传、进度、取消或回执；任何一张被拒绝，整条消息失败。
- **通用文件**：选择后上传，返回绑定会话的不透明回执；回执不是文件内容，也不是发送成功。提交时官方解析回执为 `FileAttachmentRef`，回执要到队列/历史观察后才退休。
- 提交时冻结有序内容列表（文本段、图片 data、文件回执）；附件顺序可调整，调整只改变本次列表，不重新上传未变化的字节。
- 回执未完成、已取消、属于别的会话或已 commit 未退休时，不允许再次提交同一回执；保留草稿和附件卡。
- 图片没有「回执过期」状态；通用文件回执也没有 TTL，只有会话销毁/队列移除才退休。上传响应丢失可能已保存文件，标「结果未知」，不标「未发送」。
- 移除附件只移除本地卡片；已 commit 的回执不能 revoke，也不能复用。

## 6. 失败、限额与隐私

1. 不支持的图片格式、超限、字节与声明类型不符、当前模型不支持图片输入：整条消息失败，错误码可区分原因，草稿保留。
2. 通用文件上传中断：响应丢失标「结果未知」，明确失败标「失败」；没有「回执过期」状态，不自动重发有副作用的上传。
3. 已经提交但结果未知时，不能因为附件预览还在就宣称消息已发出；按 S02 的提交状态处理。
4. 图片规范化失败不能回退成原图直传；通用文件失败不能改成「只发文件名」。
5. 日志和会话事件不输出图片 base64、完整本地路径或附件字节；wire 上的图片 base64 只存在于官方 prompt 请求，不进入持久事件。诊断只记录类型、大小、状态和错误分类。
6. 附件存储位于官方数据根，不写入业务文件夹；权限按官方存储规则。
7. 附件的持久对象在会话恢复和 fork 后可能共享；本份不实现删除或垃圾回收。
8. 子代理只收图片且需模型支持；通用文件在子代理被官方拒绝，不提供入口。

## 7. 验收

- [x] `@` 在开头/空白后触发、词内不触发；空格路径、目录下钻、相对/绝对路径和非法字符均按语法处理。
- [x] 补全只返回路径，选中后不读取文件内容；慢请求取消后不插入旧结果。
- [x] PNG/JPEG/WebP/GIF 图片可发送、可在历史中复用；图片在 wire 上是 base64 `data`，持久事件不含 base64；超限、伪造类型、损坏图片、模型不支持图片时整条失败且草稿保留。
- [x] 多图与文本的顺序在发送、历史回放和重启恢复后保持一致；每消息图片数/总字节上限按部署配置拒绝。
- [x] 通用文件按原字节保存，模型侧收到文件名/大小/摘要前缀；只有执行文件系统映射时才有只读路径，否则句柄明确说不可访问。（句柄文本由官方 `fileHandleText` 组装；本份验证到持久 `FileAttachmentRef`，未发真实模型请求。）
- [x] 通用文件回执属于会话、提交时解析、队列/历史观察后退休；跨会话回执、未完成回执、已 commit 未退休的回执都不能再次提交。
- [x] 上传中断分别显示「失败」或「结果未知」，不自动重发；没有回执过期状态；已提交附件不会因预览消失而变成「未发送」。
- [x] 子代理只收图片且需模型支持；通用文件在子代理被拒绝，不提供入口。（S12 尚未接入，当前窗口没有子代理输入入口；协议校验层已拒绝通用文件。）
- [x] 附件元数据和日志不含本地路径、provider URL、base64 或附件字节；`@path` 作为用户原文进入 prompt 不算附件元数据。
- [x] 本份的真实图片/文件链路证据与失败夹具随交付提供；未测的部署限额明确标注。

## 8. 机制清单

| 机制 | 解决什么 / 没有会怎样 | 确认与代价 |
| --- | --- | --- |
| 只补全路径的 `@file` | 不把「引用」误解成「已读取」；没有则模型可能假装看过文件 | 官方语法；补全零 token |
| 图片准入时规范化/持久化 | 会话日志不引用半成品；没有则部分附件或坏图进入历史 | 官方语义；整批失败代价 |
| 通用文件不透明上传回执 | 上传与发送解耦，提交时才校验归属；没有则跨会话串附件 | 官方契约；只服务通用文件，图片没有回执 |
| 通用文件只给句柄 | 大文件不经模型字节流；没有则上下文爆炸 | 官方语义；模型需主动读取；路径仅映射时提供 |
| 图片读时校验 | 防止缺失/损坏/替换后显示错图；没有则静默错误 | 官方语义；读取可能失败 |

## 9. 自定细节

- 附件选择器的打开方式与快捷键由 S06 定，最终键位由 S13 的 design-contract 冻结。
- 输入框内附件以紧凑卡片显示文件名/缩略图与状态；具体尺寸由 S13 的 design-contract 视觉基准决定。
- 图片缩略图只用于本地展示；wire 上的发送对象是 base64 `data`，持久引用由官方准入后生成。
- S06 不提供拖拽之外的批量导入目录功能。
- 实现期键位：`Alt+A` 打开路径输入，`Alt+Backspace` 移除光标前最近的附件卡片，`Alt+←`/`Alt+→` 调整光标前最近附件在本次列表中的顺序（只交换锚点，不重传字节）；补全面板用 `↑`/`↓` 选择、`Enter`/`Tab` 插入、`Esc` 关闭。最终键位仍由 S13 冻结。
- 卡片显示文件名、字节数、图片尺寸与状态，不渲染终端图形缩略图；这是 S13 视觉基准接管前的紧凑占位。
- 图片和通用文件都走 `nano.attachment.begin|chunk|finish|discard`，单 chunk 原始字节上限 48 KiB。图片在 bridge 内存暂存，提交时交给官方 admission；通用文件落到 `<数据根>/runtime/attachment-staging/` 的临时文件，`finish` 后由官方 `saveFileStream` 读取并删除临时文件。
- 回执 id 由客户端生成（`nano-` + 16 字节随机数），bridge 只接受安全字符并把它与根会话地址绑定；临时文件名使用独立随机 UUID，不用回执 id 作路径。
- 模型图片能力按以下顺序取路由：启动时的 `config.provider/model`、会话最近一次 `request.header`、官方 `agentDefaultModel`；只有官方模型元数据显式不含 `image` 时才在发送前拒绝。
- 协议新增方法/错误码/可选 `hello.attachmentLimits` 使 minor 升到 1；S01 的帧、生命周期和关停契约不变。
