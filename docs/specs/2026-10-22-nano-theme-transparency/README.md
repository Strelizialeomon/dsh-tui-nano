## 1. 目标与边界

目标：Nano 自有界面的功能配色不再依赖 Ghostty 默认前景或 ANSI 调色板，同时保留用户已设置的普通背景及其透明合成。主题只决定应用输出什么颜色，不接管终端如何合成窗口。

本单交付一个完整能力：共享主题定义 + 三处渲染接入 + 透明背景与颜色独立性测试 + 帮助和验收口径。配色、覆盖层与验证必须配套，不能以仅改主对话或截图好看视为完成。

范围：

- `NANO_THEME` 从局部 diff/dock 选择扩展为全部自有界面的主题选择。
- 自有文字、边框、状态、焦点/选择和 diff 使用明确 RGB；普通背景保持终端默认背景。
- 根会话、子会话、全部面板、覆盖层和内嵌终端外壳的渲染接入与回归测试。
- 移除“把 Ghostty 调成 Nano 的配色才能正确截图”的验收前提。

不做：

- 不改布局、键位、内容预算、滚动、业务状态判定、消息数据、历史、协议、桥接、凭据或官方服务。
- 不新增主题插件、设置页、持久主题文件、自动深浅探测、热切换或第二个主题环境变量。
- 不读取或修改用户 Ghostty 配置；不调整字体、字号、透明度、模糊、全屏方式、原生光标或终端原生选择色。
- 不把内嵌 shell 的显式 ANSI/索引色/RGB 输出改成 Nano 的语义色；不承诺任意壁纸、透明度或错误深浅搭配下都达到固定对比度。
- 不扩大当前 macOS arm64 + Ghostty 的正式验证范围，不把浏览器预览视为终端证据。

## 3. 主题契约

### 3.1 选择与共享

- 沿用 `NANO_THEME=dark|light`。仅精确值 `light` 选择浅色；未设置、`dark` 或其他值均回退深色，保留既有兼容行为。
- 在进程启动/应用构造边界解析一次，根会话、后建子会话、切换会话和所有面板接收同一不可变主题。不得由 dock 每帧读取环境、transcript 构造时读取环境而形成两个来源。
- 单测可显式传入深/浅主题，不依赖修改全局环境变量以免并行测试相互污染。
- 共享定义只保存语义角色、固定颜色和必要样式辅助；不承担业务状态、消息模型、终端配置或渲染布局。
- 缓存中的 styled lines 必须与主题匹配；沿用已有 theme cache key 或等价失效处理，不得返回另一主题缓存。运行中不支持热切换。

### 3.2 语义色表

色值来自现有设计稿 [preview/index.html](../../design/2026-10-17-dsh-tui-ux-research/preview/index.html)，本次把参考角色落实为应用输出的 RGB。背景例外不使用设计稿的整屏实色。下表只有一个正文 owner：本 spec。

| 角色 | dark | light |
| --- | --- | --- |
| `fg`：正文、输入、标题、普通代码 | `#e8e6e0` | `#343945` |
| `muted`：次要信息、过程、行号 | `#8d95a6` | `#626978` |
| `accent`：用户消息、强调、焦点指针 | `#7da1de` | `#365f9d` |
| `error`：错误、失败 | `#da8a93` | `#a33e4c` |
| `warning`：警示、审批、终止 | `#d8b270` | `#855b18` |
| `success`：完成、可用、已选 | `#9ac4a6` | `#315f3e` |
| `rule`：普通边框、分隔线 | `#424953` | `#c4c6c9` |
| `hover_bg`：已有 hover/dock 焦点背景 | `#242b35` | `#e8e8e5` |
| `selected_bg`：已有选择行背景 | `#3b4a66` | `#d5def2` |
| `diff_add_fg`：新增标记与统计 | `#a1c8aa` | `#315f3e` |
| `diff_del_fg`：删除标记与统计 | `#e2a0aa` | `#8f3545` |
| `diff_add_bg`：新增行背景 | `#24382c` | `#dcebdd` |
| `diff_del_bg`：删除行背景 | `#38252a` | `#f1dcdf` |
| `diff_add_word_bg`：新增词背景 | `#385b42` | `#b6d6bc` |
| `diff_del_word_bg`：删除词背景 | `#653641` | `#e9bac3` |

规则：

- 选择行前景使用 `fg`；dock 聚焦行仅使用 `hover_bg`，文字/灯颜色与字重保持原含义。
- diff 正文/词级前景用 `fg`，词级保留已有加粗；标记/统计使用各自的增删前景角色，行号用 `muted`。不新增语法高亮功能。
- 原本承担正文含义的 White/Gray/Black/default foreground 改用 `fg`；承担次要信息的 DarkGray 改用 `muted`；普通边框单独用 `rule`，不再和次要文字共用同一颜色。
- 原 Magenta 若只是分类/标题强调，归 `accent`；未知/不可用状态仍按已有业务事实取 `muted`、`warning` 或 `error`，不得因颜色迁移改判为成功。
- 自有界面不再直接输出命名 ANSI 色、`Color::Indexed` 或 reset/default 前景作为最终颜色。允许 style patch 的未指定字段继承已铺好的主题前景；终态 Buffer/协议检查负责证明没有漏色。

### 3.3 普通背景与局部高亮

- 普通背景统一为终端默认背景，Ratatui 表达为 `Color::Reset`。它不是透明度数值，也不是“填一个看起来相近的 RGB”。
- 默认前景须显式为主题 `fg`。首帧、重绘、resize、两侧边距、空白行、输入区、普通面板、覆盖层空白都必须保持这一对前景/背景。
- `Clear` 可以清除被盖住的文本，但之后必须恢复主题前景和默认背景，再绘制内容；不得以整块 RGB 面板底色遮盖旧内容。关闭覆盖层后不得残留实色矩形或透出旧文字。
- 允许显式 RGB 背景的自有范围只有：已有焦点/选择高亮、diff 增删行和词级强调。未聚焦的普通区域不新增底色；不得将 hover/selected 扩散到整屏或其他槽位。
- 自有焦点/选择用明确前景与背景，不用 `REVERSED` 间接把正文色变成大块背景；子程序原有反显和内嵌终端拖选行为不在此禁令内。
- 不发送 OSC 4/10/11/104/110/111 等全局调色板/默认色查询或修改，不发送改变透明度的私有控制序列；既有 OSC 52 复制不受影响。

### 3.4 全面覆盖与子程序边界

必须覆盖：标题、根/子 transcript、实时预览、Markdown、工具/命令输出展示、diff、输入/占位/附件、队列、补全、活动行、底栏、dock、子代理列表、会话、技能、规矩、任务、monitor、调度、命令/模型/强度/权限面板、问卷/审批/计划卡、交互终端占位/状态行/shell picker。

内嵌终端分两类：

- Nano 绘制的外壳与子程序**默认前景**使用本主题 `fg`；子程序默认背景保持终端默认背景。
- 子程序显式前景/背景、ANSI 索引色、RGB、粗体/反显、字符、光标和拖选语义保留。其显式背景可能不透明，ANSI 索引色仍可受外层终端调色板影响；该输出不是 Nano 的功能配色，不纳入“换终端主题颜色不变”的保证。
- 不在全帧结束时统一重映射所有颜色，也不升级/修改 `tui-term`、`vt100` 依赖来实现。若需调整默认前景，只作用于内嵌屏幕中未显式指定前景的单元格；必须有显式色不被覆盖的回归测试。

## 4. Ghostty 透明边界

已核：本机 `ghostty --version` 为 1.3.1；`ghostty +show-config --default --docs` 与 [官方配置参考](https://ghostty.org/docs/config/reference#background-opacity) 的相关说明一致。这是本次事实依据，不把未运行的产品实现记为已通过。

- Ghostty 的 `background-opacity` 控制默认背景合成；显式背景色是否也应用透明度由 [`background-opacity-cells`](https://ghostty.org/docs/config/reference#background-opacity-cells) 决定。本单既不代改也不要求用户开启该项。
- 本单保证的是：原本可见的普通背景不被 Nano 新增实色层遮住，启动/运行/退出不改用户透明设置。局部高亮仍按终端规则合成，不保证全部色块透明。
- macOS 原生全屏会由 Ghostty 禁用背景透明。透明专项用普通窗口；保留既有全屏功能回归，但原生全屏不作为“必须看见桌面”的判据。不要把 alternate screen（终端缓冲区）误当 macOS 原生全屏；`--no-alt-screen` 的既有含义不变。
- 终端默认背景、壁纸、色彩管理、最小对比度修正、原生选择、光标均可能影响最终视觉。独立性断言针对 Nano 发出的语义 RGB，不要求完整截图像素相等，也不承诺随意选择深浅主题都适配任意底色。

## 6. 验收与完成标准

- [ ] 三处渲染使用同一主题；根/子 view、会话切换和缓存不会混用两套颜色。测试显式注入主题，不修改并行测试共享的进程环境。
- [ ] 按 §3.4 全部 surface 列出覆盖结果。两种主题至少各验证普通正文、次要信息、边框、错误、警告、成功、焦点/选择与 diff，不以单个 dock/diff 测试代替全界面检查。
- [ ] 首帧、空白、两侧边距、60/100 列 resize、清空、覆盖层开/关后，普通区域终态背景均为 Reset、正文最终前景为主题 RGB；局部背景不越界。
- [ ] 浅/深 diff 的上下文、增删正文、行号、统计、词级强调、换行、收起/展开均取正确主题；旧深色硬编码背景断言更新为本 spec 色表。
- [ ] 内嵌终端默认前景接入主题、默认背景保持 Reset；带显式索引/RGB/反显的子程序样本保持原输出语义；F12 返回后主界面恢复，选择/复制/光标回归通过。
- [ ] Nano 自有输出协议中有预期 truecolor 前景，不靠 ANSI 槽位获得功能色，也没有全局颜色/透明度控制序列；内嵌终端显式输出按边界单独核对，既有 OSC 52 不误报。
- [ ] `nano --help` 和公开主题用法不再写“只影响 diff”，明确需重启生效、普通背景保留、局部色块和原生全屏限制。
- [ ] `cargo test --workspace`、`npm run test:bridge`、`npm run test:e2e` 及 `NANO_E2E=1 node --test tests/e2e/cross-feature.test.mjs` 按既有前置全部通过；不能把未跑项写为通过。实施后按既有入口重跑受影响的安装/发布复核。

### 6.2 真实终端证据

实施证据写入 §5 指定的新目录，保留本次构建 commit、Ghostty 版本、窗口尺寸、启动参数、主题/透明夹具和通过/失败结论。使用隔离模型/数据根与临时 Ghostty 配置，不接触用户凭据或持久终端配置。浏览器预览和静态示意图不算真实证据。

- [ ] **颜色独立性**：2 种 TUI 主题 × 2 套明显不同的终端前景/ANSI 调色板 × 60/100 列，共 8 组。正常验收不注入 Nano 色表；对照用的终端调色板仅作故意错配夹具，明确记录，不成为产品配置前提。比较 Nano 输出的语义 RGB，允许普通背景不同；不要求错误深浅搭配也有固定对比度。
- [ ] **主体透明**：普通窗口、`background-opacity=0.7`、`background-opacity-cells=false` 下，深浅 TUI 主题各测一次。窗口后放稳定、有明显边界的背景图案，启动前/运行时/退出后取同一区域证据；普通空白和面板非高亮区仍能透出图案，resize、打开/关闭命令面板后无新增实色遮挡。
- [ ] **局部底色边界**：同一临时夹具分别用 `background-opacity-cells=false/true` 记录 diff/选择/hover 的实际行为；不要求 false 下局部色块透明，不把 true 设成用户必需配置。配置内容前后哈希一致。
- [ ] **不透明回归**：普通窗口 `background-opacity=1` 至少一次，正常匹配深浅底色时可读、层级明确，未新增依赖透明才能看清的内容。
- [ ] **全屏回归**：既有 Ghostty 全屏下 60/100 列布局和交互不退化；注明实际全屏模式，不把原生全屏的终端透明限制报成 Nano 缺陷。
- [ ] **组件与退出回归**：真实证据覆盖根/子会话、diff、命令面板及关闭、决策卡、dock、调度、内嵌终端进入/返回；正常退出与错误退出后，终端颜色/透明配置未被改写。

## 7. 机制清单

| 机制 | 解决什么 | 没有会怎样 |
| --- | --- | --- |
| 一份共享语义配色定义（2026-10-22 机制卡已选「采用」） | app、transcript、terminal 外壳按正文/边框/状态等角色取同一组明确颜色；既有 `NANO_THEME` 一次选定 | 三处继续复制配色或借终端槽位，换终端主题/新增面板时出现颜色漂移 |

透明背景使用既有默认背景能力；主题选择扩展既有变量；截图对照与回归是本需求的验收，不新增运行时自动探测、透明度控制或主题插件机制。

## 8. 体量评估与结构选择

这是一个全界面配色迁移成果，三个消费者共享同一入口；没有另行发布的功能里程碑。定义、接入、测试和提 PR 是普通实施步骤，不伪装成多个阶段。

真实候选拆法：

| 候选子件 | 成果与独占范围 | 依赖与代价 |
| --- | --- | --- |
| S01 主对话与全局界面主题 | 共享主题、app、transcript、对应单测和真实主界面证据 | 提供主题 API；app 中终端状态行也由本份接入 |
| S02 内嵌终端外壳适配 | terminal 外壳与默认前景、显式色保留测试、内嵌终端/透明专项和发布验收收尾 | 消费 S01 API；可按冻结接口开发，合入需 S01 可用；最终完整验收由本份收尾 |

推荐不拆：1 spec + 1 执行 issue，同一交付完成全部覆盖与证据；没有 API 发布给外部系统的需要，单独交付半套主题对用户没有完整收益。

若选拆：1 总纲 + 2 份执行 spec + 2 张执行 issue + 1 张仅跟踪的父 issue；先补交付物地图/有方向的依赖台账和文件 owner，再逐份过闸，不把本草案直接拆成两张无规格执行单。

用户结构选择：2026-10-22 选择「不拆（推荐）」；最终为 1 份 spec + 1 张执行 issue，不另开阶段单。开始需本 spec 合并；合入需完整实现与测试；发布需沿用既有发布门槛，本单不新建发布阶段。

## 9. 自定细节

- 新共享 crate 暂定名 `nano-theme`，只依赖工作区已有 Ratatui 0.29；Rust 类型/函数名由实施按周边风格确定，不另引框架。
- 保留既有变量精确匹配与非法值回退 dark，不新增错误弹窗；主题进程内固定，修改环境后重启生效。
- 深色 diff 也统一到设计稿的柔和背景，而非继续保留当前 `#002a00` / `#300000`；具体新值见唯一色表。对实现而言是明确色值迁移，不是只移动常量。
- 选择行前景复用 `fg`；分类用的 Magenta 收敛到 `accent`。不为旧 ANSI 每个色名再造一个产品角色。
- 默认背景用 Reset，但自有默认前景不能 Reset；使用 `Clear` 后恢复基础样式。内嵌终端的显式颜色例外按 §3.4 核，不做全帧洗色。
- `0.7` 是透明专项临时夹具值，不是产品默认值；不读取/改写用户真实 Ghostty 配置。测试夹具的启动方式以本机 Ghostty 帮助核实，不冻结未经核对的 CLI 参数。
- 局部背景不透明不算主体透明失败；原生全屏透明限制不算 Nano 透明失败；两者仍须在证据里标清，不能省略专项。
- 本次不新加 CI、文档检查脚本或自动主题扫描治理工具；实施所需断言放现有测试入口或本单主题测试中。
