## 1. 目标与边界

目标：收掉用户 2026-10-22 的四条反馈，让真实 TUI 的预览提示、子代理 dock、内容块间距和输入框手感与设计稿及 Claude Code 的实际行为对齐。

范围：

- transcript 实时预览的提示文案与颜色。
- 子代理 dock 的标题、行排版、状态词、焦点样式与完成行清理。
- 标题行与主视图之间的留白。
- 输入框的上键历史回看（根：项目内跨会话；子代理：本会话内）。

不做：

- 不改协议、桥接、宿主、官方服务、凭据和数据所有权。
- 不做视觉第二批（问卷/审批/计划卡、浅色 diff token、回到最新、hover 全量）。
- 不做 Ctrl+R 历史搜索、跨项目历史、附件/图片随历史恢复、历史条目撤销。
- 不改变草稿语义：草稿仍只存内存，关窗不跨进程恢复（S02 继续有效）。

拥有：`crates/nano-app/src/ui.rs`、`crates/nano-app/src/app.rs`、`crates/nano-transcript/src/render.rs`、`crates/nano-subagents/src/{lifecycle,state}.rs` 及对应测试；`docs/evidence/2026-10-22-visual-followup/`；本 spec。

## 3. 详细规格

### 3.1 实时预览提示

- 触发：流式预览观察到 dense-index/revision 缺口，或预览达到字节上限。
- 位置：预览正文之后、单独一行，整行 muted（DarkGray），不加粗、不用 Yellow。
- 文案：
  - 缺口：`（实时预览有缺失，完整内容以最终消息为准）`
  - 超长：`（实时预览过长已截断，完整内容以最终消息为准）`
  - 两者同时成立时各占一行，按上述顺序输出。
- 每条提示都按主视图宽度换行（复用正文的换行逻辑），不截断；60 列下允许折成两行。
- 落定后的持久消息不显示该提示。

### 3.2 子代理 dock

位置与槽位不变：输入块 → 底栏 → dock，dock 在屏幕最底部；子代理视图隐藏 dock。

**标题**：顶边框只画一条线（左右各 2ch 内边距内），不嵌任何文字；`N local agents` 不再出现在 dock。计数移到「全部子代理」列表标题，保留现有键位提示：

- 已加载：`全部子代理 · N · ↑↓ 选择 · Enter 进入 · r 刷新 · Esc 关闭`
- 读取中：`全部子代理 · 读取中… · ↑↓ 选择 · r 刷新 · Esc 关闭`

N 只数**本地直接子代理**：含 Running 与尚未到 30 秒清理的终态行，不含已清理的 hidden，不含 external。列表本身是递归后代，行数可以多于 N。

**行排版**（每行一个直接子代理，最多 4 行 + 1 行溢出）：

- 焦点指针：未聚焦为 1 个空格；聚焦行为 `›`，accent（Cyan）。
- 状态灯：沿用现有 `●`/`○` 与 800ms 闪烁；颜色按官方终态，见下方状态词表。
- 名字：默认 fg，弹性占满中间；放不下时右侧截断。
- 右侧状态词：muted，只显示一个词，右对齐；不显示用时，不显示 mode（`一次性`/`不可进入`）。
- 聚焦行：只用 hover 底色，不加粗、不反显。`NANO_THEME=light` 用 `#e8e8e5`，未设置或 `dark` 用 `#242b35`；文字与灯保持原色。
- 溢出行为：`› ● 还有 N 个子代理`，整行 accent；N 是未显示的可见行数。

**状态词**（以官方 `subagent/end` 终态为准，不拿 `lastTurnCompleted` 冒充）：

| 灯 | 条件 | 状态词 |
| --- | --- | --- |
| Running | 官方 activity=running 且无终态 | `执行中` |
| Completed | stopReason=completed | `完成` |
| Warned | aborted / refusal / max-tokens | `终止` |
| Error | stopReason=error | `错误` |
| Inactive | 无终态且未运行，或 stopReason=unknown | `未运行` |

**清理**：

- `CLEANUP_DELAY` 从 1.5 秒改为 **30 秒**（对齐 Claude Code `PANEL_GRACE_MS = 30_000`）。
- 所有官方 `subagent/end` 都进入清理队列，不区分 continuable / one-shot / external；30 秒内状态词保留，到期从 dock 移除。
- 记录不删除：仍在 catalog 和「全部子代理」列表中；`Alt+L` 可找回。
- 同一 child 再次 `subagent/start` 时清除 hidden 标记，重新出现在 dock。
- 正在查看的子代理详情不因 dock 清理而关闭。

### 3.3 内容块间距

- 条目之间保持 **1 行空白**（维持现行每个条目末尾 1 个 `Line::default()`，不增加到 2 行）。
- Markdown 段落之间保持 1 行空白。
- 新增：标题行之后、主视图之前固定 1 行空白（设计稿 `.viewport-shell` 的 `margin-top: var(--line)`）。子代理详情头（标题 + 子代理行）之后同样留 1 行。
- 主视图底部不额外加行：最后一个条目自带的 1 行空白即是底边留白。

### 3.4 输入框历史回看

**文件**

- 路径：`<data_root>/history.jsonl`。`data_root` 取自宿主链接解析结果（默认 `~/.dsh-tui-nano`）。
- 每行一个 JSON 对象：`{"display":"…","timestamp":<epoch ms>,"project":"<canonical cwd>","sessionId":"<root session id>"}`。
- 权限：创建时 0600，只追加；父目录由运行时保证私有。
- 写入失败不阻塞提交、不弹错误；静默跳过。
- 不写附件/图片，不写队列编辑，不写子代理输入。

**写入时机**

- 根输入框每次非空提交时追加一条，包含斜杠命令和 `!` 人工命令的原始文本。
- 发送失败也保留（与 Claude Code 一致：提交即记录）。
- 同一文本重复提交不去重。

**读取与排序**

- 每次从「非浏览态」按上键进入历史时，从文件尾部向上扫描，凑满 100 条当前项目记录即停；跳过损坏行和空 display。
- 排序：先当前 `sessionId` 的记录（新→旧），再同项目其它会话的记录（新→旧）；总计最多 100 条。
- 读取失败按空历史处理，不弹错误。
- 进入浏览时对条目做快照；浏览期间文件变化不影响当前快照。

**键位与优先级**

- 前置条件：输入框聚焦、补全弹层未打开、`edit_target` 为空（队列编辑中 ↑↓ 归队列编辑）。子代理输入框还要求 mounted gate 的 `can_send()` 为真；只读/仅停止/读取历史中时，↑↓ 仍被 gate 吞掉，不进入历史。
- 输入框聚焦且上述条件成立时，`↑`/`↓` 才进入历史逻辑。
- `↑`：光标在首行时，若有历史则进入/继续历史；若历史为空且草稿为空，则聚焦 dock。光标不在首行时保持普通光标上移。
- `↓`：处于历史浏览时向新条目回看；越到最新一条后再按一次，恢复进入前的草稿与光标。非浏览态且草稿为空时聚焦 dock；否则保持普通光标下移。
- 浏览中，`↑` 仍要求光标在首行、`↓` 仍要求光标在末行；多行条目内先按普通光标移动，到边界后才翻历史。
- dock 聚焦后 `↑`/`↓` 归 dock，不再进入历史。
- 进入历史时保存当前草稿文本与光标；上键回看条目光标落行首，下键换条目光标落行末，恢复草稿时回到进入前光标。
- 浏览中打字/粘贴/退格/删除/换行：退出浏览，保留已回看的文本作为草稿。
- 提交、Ctrl+U、队列编辑：退出浏览。
- 浏览中按 `↑` 到最旧一条后停住，不循环。
- 补全弹层可见时，`↑`/`↓` 先归补全（现有优先级）。`Esc` 保持现有含义（停止回合/取消压缩/取消人工命令/取消队列编辑），不恢复草稿。`Tab` 切焦点的既有行为不变；浏览态保留，回到输入框后继续生效。

**子代理输入框**

- 子代理输入框也支持 `↑`/`↓` 历史，但只在本会话内，来源是该子地址的 `active_model()` 投影，且只取 `MessageKind::User`（不取 SyntheticBash/Injected/Monitor/Notice）。
- 该投影有界：`MAX_HISTORY_ITEMS = 2000`，超出或回放窗口截断时只能回看保留窗口内的用户消息；界面不额外提示。
- 不写根历史文件，不跨会话。
- 除数据来源外，键位、草稿保存/恢复与浏览退出规则同根输入框。

**范围外**

- Ctrl+R 搜索、历史删除/撤销、跨项目历史、附件随历史恢复、子代理历史跨会话。

## 6. 机制清单

| 机制 | 解决什么 | 没有会怎样 |
| --- | --- | --- |
| 根输入历史文件（项目内跨会话、最多 100 条） | 上键能回看已提交输入，重开/新会话仍可用 | 上键只能移动光标，用户要重新输入长提示。 |
| 子代理输入历史（本会话内） | 在子代理输入框里也能上键回看该子地址的已提交输入 | 进入子代理后只能移动光标，无法复用刚发过的提示。 |
| `NANO_THEME` 主题选择（首次读取，先用于 dock 焦点底色） | 焦点行在深/浅终端下都用对应 hover 底色 | 只能用固定反显或高对比选中色，与设计稿的 hover 不一致。 |

其余三项是呈现/行为修正，不新增机制：预览文案、dock 排版与 30 秒清理、标题下留白。

## 7. 自定细节

- 历史文件固定为 `<data_root>/history.jsonl`；不新增第二个路径或环境变量。
- `project` 取宿主 hello 的 canonical cwd；`sessionId` 取当前根会话 id；恢复同一会话时仍算当前会话。
- 单条 `display` 原样存储，不截断、不做 paste store；大段粘贴会占文件空间，由用户输入量决定。
- 历史读取从文件尾部扫描，最多凑 100 条；损坏 JSON 行跳过。
- 写入用单次追加，不跨进程加锁；同一行的完整写入由 O_APPEND 保证。
- 历史文件不记录附件、图片、队列编辑、子代理输入。
- 子代理输入的历史来自其 `active_model()` 的 `MessageKind::User` 投影，受 `MAX_HISTORY_ITEMS = 2000` 与回放窗口上限约束；不落历史文件，只在当前进程内按子地址回看，切换子地址后重新读取该地址的消息。
- dock 主题底色用 `NANO_THEME`：未设置或 `dark` 用 `#242b35`，`light` 用 `#e8e8e5`；这是 `NANO_THEME` 的首次读取，batch 2 的 diff token 继续沿用。

- 历史浏览时按上键光标落到条目行首；按下键换到更旧/更新条目时光标落到行末；恢复草稿时回到进入前光标。
