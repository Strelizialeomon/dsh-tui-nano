M1–M3 已由用户选择“全部纳入”。后续追加了代码变更展示、长差异折叠、代码与 Bash 整块单击开关，以及参考 pi-plugins 的选项卡；两个额外差异操作按钮已移除。产品源码和用户配置未修改。

## 子代理交互

当前样稿采用“原对话 → 子代理详情 → 返回”的从属导航。子代理属于发起委派的对话，不是与原对话并列的独立聊天；界面中不再出现“主代理”切换项。

- 原对话底部最多列出 4 个子代理，多余的合为一行入口。底部和全部列表都不列父级对话。
- 鼠标点击、列表聚焦后的 Enter / → / Space 进入子代理详情。进入后隐藏原对话的同级任务列表，顶部只标识“子代理”和任务名称。
- 子代理内不论焦点在输入框、正文、工具详情或发送按钮，Esc 都直接退出；顶部退出按钮和空输入时 ← 执行同一个返回动作。不必先把焦点交回输入框。
- 从底部进入的，退出后回原对话及对应入口；从全部列表进入的，退出后回该列表和选中行，再按 Esc 关闭列表。原对话草稿、光标和阅读位置保留；已消失的入口回退到输入框。
- 子代理的输入只属于该子代理，Enter 追加本地演示消息，Shift+Enter 换行；中文输入确认不提交。退出只结束查看，不停止任务，也不丢弃子代理草稿与阅读位置。
- 沿用本项目已确认的完结态规则：成功、失败、终止均在约 1.5 秒后退出底部列表。当前子代理详情不会被定时关闭，原对话保留结果入口，消失不等于丢失记录。
- 工具详情、滚动与“回到最新”作用于当前可见内容；100/60 列及移动窗口保持输入可用。当前演示只有一层子代理，不额外引入嵌套任务。

本轮只更新样稿、说明和浏览器回归；项目规格、Issue 与 TUI 产品源码没有改动。

## 底部与上下文容量线

底部采用极简档，只保留权限/安全状态、运行或错误瞬态和工作目录。模型、上下文数字、缓存、成本、Token 不常驻；`Ctrl+O` 不是底部提示，它继续作为全局详情/转录查看快捷键出现在帮助与快捷键说明中。

输入框上下边框的左侧色段表示上下文占用，顶部和底部同步；剩余部分保持普通边框色。样稿不写百分比，不恢复独立上下文条，准确数值仍从 `/tokens`、`/status` 查看。边框的色段随场景压力改变：正常为强调色，约 80% 为 warning，约 95% 为 error；未知时整条回退普通边框。

样稿中的浅蓝边框表示正常占用，右侧未着色部分表示剩余空间。它验证的是视觉结构，不是实际 token 计算。

## 这版具体改变什么

| 区域 | 推荐默认 | 用户如何看详情 |
| --- | --- | --- |
| 回答 | 正常亮度；结论、小标题加粗；段落间隔一行 | 原文直接阅读、选择和复制 |
| 提问 | 固定前缀与强调色 | 原文保留 |
| 思考 | 单行状态与用时；正文默认收起 | 点击该行展开；沿用全局详情入口 |
| 命令 | 首个可视行＋隐藏行数＋状态；长标题省略 | 点击命令/输出内容展开；再点该块收起 |
| 运行输出 | 最新 2 个可视行；只在原位更新 | 展开该条查看更多内容 |
| 完成输出 | 有依据的简短结果或退出状态；详细输出收起 | 展开该条查看完整可用结果 |
| 失败 | 独立显示错误摘要与退出状态 | 完整错误记录在详情中 |
| 审批 | 完整待执行命令直接显示；长内容可滚动 | 审批所需信息不服从聊天卡片的紧凑预算 |
| 底部与上下文 | 底部只保留权限/安全、运行或错误瞬态和工作目录；模型、上下文数字、缓存、成本、Token、Ctrl+O 不常驻 | 上下文占用显示在输入框上下边框的同步色段，精确数值走 `/tokens`、`/status` |
| Subagent Dock | 仅列当前对话的子代理，最多 4 行，多余折叠；不列父级对话 | 点击/Enter/→ 进入子代理详情，并隐藏同级列表；Esc 退出回原入口，保留草稿与阅读位置 |
| 代码变更 | 文件名、增删统计、真实行号、整行底色与行内强调；代码区最多 8 个可视行 | 长变更整块内容可单击开关；无额外操作按钮 |
| 选项卡 | 单列编号；焦点和已选分开；描述另起一行 | 单选直选，多选勾选，多题可回看；其他答案行内输入 |
| 底栏 | 模型、上下文及必要模式信息保持可读 | 仍遵循用户已有字段选择 |

单条展开后，不因工具完成或另一条消息到达自动收起。代码与 Bash 统一在内容区域单击开关，原位完成，无过渡动画；拖选、复制与专用链接操作优先。默认摘要只改变显示，不改变会话记录、模型上下文和工具实际输出。未知结果、未结束状态不能显示成成功。

样稿中的结论和小标题来自演示内容的 Markdown 结构；实际界面只呈现传入结构，不自动猜测哪一句是最终回答。首版保留全部面向用户的助手文字。

## 代码变更与长内容

窄屏代码块采用统一差异：中性上下文、红色系删除底色、绿色系新增底色；实际变化的片段再强调。文件名与准确增删统计放在块头；有真实 patch 坐标才显示行号。待应用与已应用状态明确区分。

短改动直接看完。长改动默认最多 8 个可视代码行，优先保留第一处完整变更；多个修改段共享预算。示例中的 31 个显示行只先显示第一处的 6 行，余下 25 行明确提示，避免把下一处的删增对切开。超长单行的换行同样计入预算。

用户已要求移除“复制修改后代码”和“展开原始差异”两个按钮，样稿及规格均不再提供这两个功能。长差异复用整块内容点击与 Ctrl+O，展开后仍是同样的差异呈现；再点内容即可收起，保留普通选择复制。

本机 Claude Code 2.1.302 的 Edit 结果有摘要/折叠与详细分支，另一条命令文件差异路径有 40 个源行预览预算；长单行还有 2000 字符的呈现保护。这些是不同入口的本机实现观察，不是所有视图统一的产品承诺。本项目建议最多 8 个可视行，依据自己的现有预算和窄屏目标，不照搬这些数值。官方依据与观察边界见[调查报告](../README.md)。

## Pi 风格选项卡

已读取 pi-plugins 的现行 `question-card-ui.ts`、`question-card.ts` 与已实施规格。采用单列编号、标题/说明分行、独立焦点指针与勾选、单选 Enter/数字直选、多选空格勾选、行内 Other，以及多题标签与最后提交。

样稿新增“选项卡”页签，右侧可切换单选、多选、多题。普通问卷的选项由问题提供；授权卡只用相同视觉语言，仍然仅提供后端允许的结果。DSH 的允许一次/拒绝不会被擅自扩成始终允许、Other 或先讨论。

当前项目的问卷结果是 `selected/custom`，没有 Pi 的独立备注与 `chat` 结果。因此首版不画无法可靠回传的 Notes/Chat 空入口；现有本地向导、秘密输入和特殊计划面板的能力仍须保留。

“等待确认”是既有授权流程的边界样例：只在后端请求权限时出现，先说明动作和授权原因，命令可滚动核对。这次不新增每条 Bash 必须点确认的步骤。

## 克制的视觉规则

- 应用自带的装饰性 emoji 默认 0 个；使用文字与少量固定符号。原文、代码和日志中的字符不被过滤。
- 主会话保留 1 处低频字符忙碌指示；样稿每 500ms 更新一次，减少动态效果的系统偏好会使其静止。具体终端策略在规格中确认。
- 已完成工具、思考与任务保持静态；错误靠“失败”文字、退出状态和少量状态色表达。
- 正文采用当前主题的正常文字色。次要内容降低强调程度，但仍应清楚可读。颜色服务于主次和状态。
- 保留当前字体及终端字号控制。终端样稿全部为 14px；这个数字只服务于浏览器展示，不是拟强制写入用户终端的设置。
- 静态标题替代默认开屏动画的方向保留；个性化外观可以通过已有设置主动选择。显式保存的用户偏好优先于新默认。

样稿沿用现有主题的色彩方向，浅色次要文字使用更易读的现有次级色。颜色只用于展示方向，尚未确定生产色值或修改所有主题。

## 首版范围

建议纳入：

1. 回答、提问、过程、错误的层级统一；保留 Markdown 和完整用户内容。
2. 思考单行摘要、命令与输出的可视行预算、逐条展开与可复制详情；代码变更有独立层级与长内容折叠。
3. 聊天、子任务、底栏中装饰性 emoji 与持续动效的收敛；必要状态仍可访问。
4. 普通问卷与授权选择参考 Pi 卡片，保持后端结果契约、权限限制及本项目挂载能力。
5. 正文、底栏、侧栏的滚轮处理一致；方向反转和切换滚动目标时的状态边界明确；源码设置与旧补丁的迁移边界明确。
6. 折叠、流式输出完成与宽度变化时，保护正在阅读的内容位置。

后续可选：整轮工具汇总、只保留最终回答的 Focus 视图、专门的实时调速面板。首版使用现有详情与设置入口，避免同时引入多套阅读模式。原始调研中的工具汇总示意属于后续方向，本样稿展示首版的逐条记录。

减少 emoji 与动画的性能收益尚未实测；滚动性能仍需以真实终端输入回放、帧间隔和输入到显示延迟为依据。旧补丁的数字不能直接作为跨终端默认值。

## 已确认的机制清单

M1–M3 已确认，M4 来自用户后续指定的 Pi 选项卡方向。配色与符号调整可独立做，但不能覆盖过程过量、滚动不一致和选择交互的问题。

| 新增或调整的规则 | 解决什么；不做会怎样 | 代价 |
| --- | --- | --- |
| M1 思考正文默认折叠，保留单条展开选择 | 生成时保持单行；沿用动态预览仍会持续吸引注意力 | 查看正文多 1 次展开；已有全文偏好需兼容 |
| M2 命令与输出按可视行限高 | 长脚本、宽字符换行也有明确预算；只按源文本行数截断仍可能占满屏幕 | 全文多 1 次展开；失败与审批需独立覆盖 |
| M3 滚轮输入统一处理，按目标和方向管理手势状态 | 消除指针位置改变速度、反向继承加速等差异；沿用多入口仍会不一致 | 迁移安装补丁；正文、底栏、侧栏 3 类入口都需回归 |
| M4 Pi 风格选项卡（后续明确追加） | 让焦点、勾选、行内输入与多题回看一致 | 多题末屏增加一次整体确认；单题保持直接提交，沿用现有结果字段 |

首版采用 M1–M3，并纳入后续追加的代码变更、整块开关和 M4 选项卡；少装饰与层级清晰作为共同约束。无需新增主题框架、图标注册系统或更多显示模式。

## 自定细节

这些是样稿中的建议值，尚不是用户确认的最终规格：

- 默认脚本标题 1 个可视行，运行输出 2 个可视行；完成状态保留一条摘要或明确退出状态。
- 忙碌指示示意为 500ms；只保留一处持续变化。
- 详情复用点击和现有 Ctrl+O；不再发明新快捷键。
- 保留显式全文、动画与字段偏好；新安装及未设置项使用新默认。
- 100/60 列和深浅主题作为本次样稿检查范围；实际终端仍需覆盖 inline/fullscreen、鼠标与触控板。
- 不从助手文案猜测最终回答，不额外调用模型生成执行摘要。
- 不以界面简化为由替用户切换权限模式、推理设置或工具配置。
